# METRICS — Synapse

Для каждой фазы ИИ-агент предлагает проверяемые показатели. Ниже минимальный набор.
Правило: **показатель должен быть измерим существующей командой, процедурой или журналом**.
Показатель без способа измерения в отчёт не включается.

---

## 1. Создание игры

| Метрика | Как измеряется | Целевой ориентир |
|---|---|---|
| Сколько авторов дошли от пустого проекта до запускаемой игры | Журнал запусков CLI / отчёты миссий | Фаза 2: все participating authors |
| Время до первого рабочего результата | Замер от создания проекта до первого успешного запуска | 30 минут у ИИ-агента, 2 часа у человека |
| Сколько ошибок валидатор объяснил понятно | Разбор сообщений валидатора вручную на тестовой когорте | Рост доли понятных сообщений |
| Сколько действий пришлось вручную исправлять разработчику | Счётчик ручных вмешательств в миссии | Снижение до нуля |

---

## 2. Модули и архитектура

| Метрика | Как измеряется | Критерий |
|---|---|---|
| Можно ли собрать второй прототип без изменений ядра | Фаза 3: diff ядра между прототипами | Изменения ядра не требуются |
| Число несовместимостей, обнаруженных до запуска | Журнал валидатора | Рост — признак работающей проверки |
| Случаи дублирования или разрастания универсальных абстракций | Ревизия кода | Ноль новых универсальных модулей без доказанной необходимости |
| Наличие проверок вида `if genre == ...` в ядре | grep по ядру | **Ноль.** Наличие — пересмотр архитектуры |
| Смена визуальной темы меняет игровые правила | Тест на хитбоксы, правила боя, проходимые области | Не меняет. Меняет — возврат миссии |

## 3. Мастерская

| Метрика | Как измеряется | Ориентир |
|---|---|---|
| Сколько авторов опубликовали игру | Журнал публикаций | Фаза 4: 10–30 авторов |
| Сколько вернулись с новой версией | История релизов | Это **главный** признак успеха |
| Сколько публикаций скачивали и запускали | Счётчик загрузок + подтверждённые запуски | Считаем запуски, не только скачивания |
| Фактический объём хранения | Метрика хранилища | Сверка с COST_MODEL.md |
| Стоимость одного скачивания | Расходы ÷ число скачиваний | Снижение |
| Число жалоб, снятий с публикации и обращений в поддержку | Журнал модерации | Понятная нагрузка на модерацию |

**Важно:** количество зарегистрированных аккаунтов само по себе **не** является успехом.
Считаем повторное использование: автор создал игру → опубликовал → вернулся с обновлением →
игрок нашёл и запустил.

## 4. Онлайн

| Метрика | Как измеряется | Ориентир |
|---|---|---|
| Число успешных подключений | Журнал сессий | Фаза 6: 20–100 одновременных участников |
| Число отключений и сбоев | Журнал сессий | Доля сбоев снижается |
| Стоимость на игровую сессию | Расходы ÷ число сессий | Только для инфраструктуры платформы |
| Доля сессий на community-серверах и на инфраструктуре платформы | Реестр сессий | Понимать соотношение до решения о managed-хостинге |
| Отображение недоступного сервера | Ручная проверка | Явное, без «вечного ожидания» |

## 6. Метрики процесса (внутренние, для Warden и Coordinator)

| Метрика | Зачем |
|---|---|
| Доля карточек, принятых с первого раза | Качество оракула и формулировок Coordinator |
| Число возвратов миссии на доработку | Признак неполного ТЗ или неверного Scope |
| Число ADR, оставшихся без ответа | Видимый долг; дефолт и истечение срока решением не считаются |
| Число ручных вмешательств Мастера | Должно стремиться к нулю |
| Доля отчётов с подтверждаемым PR | Проверка честности сдачи |

---

## 7. Чего мы не делаем

- Не считаем количество аккаунтов критерием перехода между фазами.
- Не называем незапущенную или выполняющуюся проверку успешной.
- Не подгоняем ожидаемый результат под код.
- Не считаем `not run` равным `pass`.
- Не используем мок или локальную имитацию как доказательство живого цикла.
