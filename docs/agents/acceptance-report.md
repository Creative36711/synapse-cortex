## D-040 (1.12.5): маркер без dispatch_id/run_id — напоминание с точными ID, а не сразу пауза
После D-039 доставка K-21 **прошла** (17:21:18, 6642 зн.), Executor Core реально
выполнил работу и слил PR Creative36711/synapse#8. Но в 17:30:21 цикл встал: «Ответ
не подтверждён для текущей карточки и попытки (dispatch_id / run_id)». **Виновник —
агент:** финальный маркер пришёл как `CF_AGENT_RESULT: {"task":"K-21",…,"merged":true,
"pr":…}` — с двоеточием, с `task` вместо `dispatch_id`/`run_id` и без `status`.
Транспорт **верно отказал** в подтверждении (защита от зачёта чужой/прошлой попытки),
но ветка mismatch сразу ушла в паузу, минуя лестницу напоминаний: работа сделана, а
цикл требует ручного вмешательства. Что сделано:

- **`dispatchIdState(result, expect)`** различает `match` / `missing` / `conflict`.
  `missing` (ни один присутствующий ID не противоречит выдаче, но ID не хватает) —
  формат-дефект, а не чужой ответ.
- **`missing` → напоминание** через существующую лестницу `markerMissing(…, why="ids")`
  (до `markerReminders=2` раз). Блок `reminder.marker` с `why=ids` просит повторить
  **только маркер** с точными `dispatch_id`/`run_id` из напоминания, работу не
  переделывать. Копия ответа сохраняется локально до классификации.
- **`conflict` (чужие/битые/противоречащие ID) → прежняя сразу-пауза**
  `marker-mismatch`: возможен ответ прошлой выдачи, его не принимаем.
- **Проверка ID не ослаблена:** значения не подменяются (`adoptIds`), запись в Notion
  по неверному ID не идёт; после исчерпания напоминаний — пауза. Бюджеты **не подняты**
  (`reminder.marker` overhead ≤700, total ≤900).
- **Регрессия:** новая `relay-marker-ids-reminder-integration` — `dispatchIdState` на
  боевом маркере K-21 (`missing`), конфликт/битые/противоречащие синонимы (`conflict`),
  короткие синонимы (`match`); пины маршрутизации `submitExecutor` и `reminder.marker`
  `why=ids` в тотал-бюджете 900 с точными ID. `relay-review-dispatch-integration`
  обновлён: «нет run/dispatch сдачи» → напоминание `ids`, чужие ID → пауза (защита
  сохранена, ID не подменяются, запись не идёт).

Прогоны: `verify` — **106 smoke / 18 regression / 2 tool-limit, exit 0**;
`test:provision` — **28/28**; `docs-smoke` OK (protocolVersion 1.9). Тесты не
ослаблялись: изменился только маршрут «ID нет» (пауза → напоминание), маршрут «ID
чужие» остался паузой. Gateway и digest не менялись.

## D-039 (1.12.4): total-лимит Executor 7500 — боевая K-21 с крупным оракулом доставляется
После обновления до 1.12.3 overhead-гейт прошёл (зона стала verbatim), но боевая
K-21 упёрлась во **второй** гейт: `total 6642 > жёсткого лимита 6500 executor.card`,
пауза `budget_exceeded`, карточка возвращена в Ready — цикл остановился снова
(16:52:10). **Причина:** избыток — подлинный контент задачи (оракул/инварианты/Scope),
который не режется молча (D-034) и не уходит в payload (оракул остаётся inline).
Overhead уже lean после D-036 (диета) и D-038 (зона verbatim, ~2678, не зависит от
зоны); связывающее ограничение — total-лимит. Что сделано:

- **Total-лимит Executor поднят 6500 → 7500** (`DISPATCH_TOTAL.Executor`) — как у
  Координатора. Это **явное бюджетное решение**, санкционированный D-036 шаг
  «сначала диета/вынос фактов в verbatim, и только потом явное решение о бюджете»:
  диета (D-036) и verbatim-зона (D-038) уже исчерпаны, дальше резать нечего без
  потери правил или контента задачи.
- **Overhead-бюджет 2800 не менялся** — поднят только total-лимит выдачи.
- **Оракул не режется:** карточка между мягким 6000 и жёстким 7500 доставляется
  стратегией compact с ТЕМ ЖЕ полным контентом (это штатное поведение,
  `delivery-smoke` §2 «compact (тот же смысл)`); оракул/инварианты/Scope целы.
- **Регрессия:** `prompts-smoke` §17 — карточка K-21 total >6500 и ≤7500 со старым
  лимитом даёт паузу, с новым доставляется целиком; оракул и инварианты не порезаны;
  пин `DISPATCH_TOTAL.Executor=7500`.

Замер: боевая K-21 (total 6642) при лимите 6500 → пауза, при 7500 → доставка целиком
(оракул/инварианты intact). Arena принимает сообщения больше 7500 (боевая доставка
ответа ADR была 11637 зн.). `docs-smoke` переведён на protocolVersion 1.8. Тесты не
ослаблялись. Gateway и digest не менялись. Карточки больше 7500 — через payload-канал
D-034 (для assignment) или отдельное явное решение.

## D-038 (1.12.3): зона роли как verbatim-факт — длинная зона Executor не пробивает бюджет
Боевая выдача K-21 → Executor Core («Исправить offline NOTICE verifier без потери
атрибуций») встала на паузу `budget_exceeded` (overhead 2859 > 2800 `executor.card`).
Ход не передан. **Виноват пробел D-036:** его регрессия закрыла `auditor.card` и
`coordinator.plan` с длинной зоной, но `executor.card` с длинной зоной не проверялся.
Зона роли (~158 зн.) инлайнилась в `authority.core` и считалась overhead, съедая
запас. Что сделано (бюджеты **не подняты**):

- **Зона — verbatim-факт:** новый блок `role.zone` (`Зона роли: <зона>`) вынесен как
  факт (аналогично `task.scope`) и не входит в overhead. `authority.core` больше не
  инлайнит зону и несёт только правило о зонах.
- **Зона видна всем ролям:** `role.zone` добавлен во все 4 профиля с `authority.core`
  (executor/auditor/coordinator/reviewer) и запрещён в continuation/pilot.
- **Без дубля команды мержа:** `authority.executor` больше не повторяет
  `gh pr merge <N> --squash` — команда остаётся в `git.executor`.
- **Регрессия с боевой зоной:** `prompts-smoke` §16 (K-21 с длинной зоной Executor
  Core ≤2800; зона видна целиком и verbatim; overhead не зависит от длины зоны;
  Executor по-прежнему учит pr/merged; команда мержа в `git.executor`).

Замер: K-21 с длинной зоной — overhead ~2678 (запас ~122); overhead одинаков при
зоне 158/250/400 зн. (зона — verbatim). `docs-smoke` переведён на protocolVersion 1.7.
Тесты не ослаблялись. Gateway и digest не менялись. Coverage 16 ruleId не изменился
(`role.zone` без ruleIds, правило о зонах несёт `authority.core`).

## D-037 (1.12.2): мультирепо-сторож ADR — предложение второго репозитория доходит до приёмки
Боевой вопрос по ADR `SYN-1` (репозиторий `synapse`) завис в «Ждёт»: Координатор
задал вопрос со ссылкой на файл, предохранитель «приёмка читает файл, а не пересказ»
законно отказал дважды («полный текст не совпадает с Git blob SHA», затем «ещё не
содержит полный текст с SHA»), и ход ушёл дальше по очереди. **Виноват транспорт:**
сторож `refreshDecisions` читал `docs/decisions` только главного репозитория профиля
`synapse-cortex`, где этой папки нет (404). Запрос уходил в catch и возвращал пустой
снимок — полный текст с SHA не дописывался в вопрос, самолечения не было. Что сделано
(бюджеты промптов **не подняты**):

- **Обход всех репозиториев:** `refreshDecisions` итерирует `C.repos` (fallback на
  single-repo `C.repo`/`C.branch` для обратной совместимости).
- **404 не роняет обход:** отсутствие папки `docs/decisions` в одном репозитории
  (`e.status === 404`) пропускается, остальные репозитории опрашиваются; прочая ошибка
  по-прежнему возвращает прежний снимок.
- **Составной кэш:** `cfn-adr-text` ключуется `repo/file`; плоские ключи до D-037
  мигрируются под главный репозиторий и не смешиваются с другими.
- **Строка несёт repo/branch:** `proposalQuestion` строит ссылку и ключ дедупликации
  (`adr-full:`/`adr-full-confirm:`) из репозитория самого предложения; строки без
  `repo` (наследие) дают прежний формат ключа.
- **Точнее сообщение отказа:** когда полного текста ещё нет вообще, лог пишет «сторож
  ещё не дописал полный текст файла с Git blob SHA», а не «не совпадает с SHA».

Регрессия `relay-adr-multirepo-integration`: главный репозиторий без папки decisions
(404) не роняет обход; предложение второго репозитория найдено, несёт `repo`/`branch`,
доходит до доставки; ссылка и ключ из репозитория предложения; миграция плоского кэша;
обратная совместимость single-repo. `docs-smoke` переведён на protocolVersion 1.6.
Тесты не ослаблялись. Gateway и digest не менялись. Ограничение: дедупликация по имени
файла кросс-репо — имена ADR должны быть уникальны в профиле.

## D-035 (1.12.0): маркер Координатора с первого раза + артефакты не в корне
Два дефекта боевой миссии SYN-1. Что сделано (бюджеты **не подняты**):

- **Прайм маркера Координатора.** Маркер стоял только в конце длинного
  `coordinator.plan`, и после десятка tool-вызовов Координатор его «не видел»,
  честно отказываясь выдать («формат не виден, по памяти не восстанавливаю»).
  Теперь `coordinator.plan`/`coordinator.recovery` открывает блок `coordinator.prime`
  («заверши ход маркером последней строки; формат и IDs — в конце»). Авторитетный
  маркер остаётся последним блоком; прайм не несёт литерал маркера и не `marker.*`,
  инвариант «ровно один маркер» сохранён.
- **Адрес артефактов в промпте.** Раскладку Drive видел только Координатор, поэтому
  аудитор клал отчёты то в `artifacts`, то в корень. Теперь
  `executor.card`/`auditor.card`/`reviewer.card` несут блок `drive.artifacts`
  («Артефакты в `Arena/<project>/artifacts`, не корень Диска; ссылки в поле
  `artifacts`»); проект из профиля (`driveFolder`). Блок влезает в `auditor.card`
  ≤2200 без подъёма бюджета (K-17 проходит, скелет ≤2050).
- **Уборка в Drive.** Отчёты «SYN-1 K-17 O-4…» и «SYN-1 K-19 O-5…» перенесены из
  корня Диска в `artifacts` (`1fXMP8Fj…`). Перенос не меняет ID/URL (ссылки в
  журналах/карточках валидны), имена сохранены (ретро-переименование запрещено D-031).

Новые пробы: `prompts-smoke` §12 (прайм маркера: первый блок, маркер последний, без
литерала в прайме), §13 (адрес артефактов у Executor/Auditor/Reviewer, проект из ctx,
`drive.layout` не утекает исполнителю). `docs-smoke` переведён на protocolVersion 1.4.
Тесты не ослаблялись. Gateway и digest не менялись.

## D-034 (1.11.0): бюджет overhead + payload-канал
Инцидент K-17 → Spec Auditor: пауза `budget_exceeded` (overhead 2290 > 2200,
`auditor.card`). Причина — фиксированный скелет промпта съедал почти весь бюджет;
координатор регламент не нарушал. Что сделано:

- **Overhead-диета без подъёма бюджетов.** Дедупликация base-ветки в
  `git.executor`/`git.auditor`, короче `repo.target` и заглушка `task.assignment`.
  K-17-подобная карточка компилируется в `auditor.card` ≤2200 (регрессия в
  `prompts-smoke`). Версии изменённых блоков подняты до 2.
- **Диагностируемая пауза.** `budget_exceeded` несёт разбивку по блокам; пауза
  называет топ блоков, съевших overhead (`budgetBreakdownLine`).
- **Payload-канал.** Большое задание (> `payloadInlineMax`=1500 зн.) фиксируется
  снимком `savePayload` на прогон (`<dispatch>_<run>__assignment.md`) и доставляется
  verbatim-указателем; оракул/Scope остаются inline. Стратегия
  `full → payload-указатель → compact → pause`. Отказ шлюза — явная ошибка.
- **Total-лимиты в боевом пути.** `DISPATCH_TOTAL` (Executor 6500 / Auditor 5500 /
  Reviewer 7000) соблюдается доставкой.

Новые/обновлённые пробы: `prompts-smoke` §9–11 (K-17, указатель, разбивка),
`delivery-smoke` §2b (payload-стратегия), новая интеграционная
`regression-tests/relay-payload-channel-integration.mjs` (снимок+указатель, отказ
шлюза, малое задание инлайном). `docs-smoke` переведён на protocolVersion 1.3.
Тесты не ослаблялись. Живой Drive/боевые Notion не затронуты.

## Инструкция Мастеру
1. Обновить ScriptCat до 1.10.0; развернуть Gateway 1.8.0 тем же ключом (папки и
   история сохраняются). Автоцикл остановить.
2. В профиле включить provisioning, задать allowlist точных `owner/repo`, bootstrap-пробник,
   лимиты, режим manual. В Notion добавить аддитивные поля и отметить `Agent Admin=true`
   у действующего Coordinator/Reviewer.
3. Создать тестовую роль: `Agent State=запрошен`, пустой Agent URL, repo из allowlist.
   Нажать «🤖 Агенты» → запрос → одобрение маркером. Проверить URL/rename/Активна/Кому.
4. Заменить временную роль: заполнить URL, `Agent State=запрошен`; проверить Previous Agent URL
   и архив старого. Негативные: чужой request_id, repo вне allowlist, админ-кандидат, conflict.
5. Откат: выключить provisioning, снять `Agent State`, вернуть прежний URL/Статус вручную;
   старый URL при replace хранится в `Previous Agent URL`. Новая сессия при захваченном URL
   повторно не создаётся.
