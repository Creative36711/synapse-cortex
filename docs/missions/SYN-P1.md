# SYN-P1 · Внешний пилот — черновик ТЗ (v0.1, 2026-11-03)

Статус: **черновик**. Запуск требует действий Мастера (создание одноразовых агентов в Arena) —
поэтому миссия не стартует без его команды. Решение о подходе — D-029.

## 1. Цель

Проверить главную гипотезу продукта: **ИИ-автор, не знающий проекта, может сделать работающую игру,
читая только публичную документацию `Creative36711/synapse`.** Не «код работает» (это проверяют
оракулы K-миссий), а «путь автора проходим без подсказок».

## 2. Что проверяется и чем

| # | Критерий | Как проверяется |
|---|---|---|
| P-1 | Путь проходим без подсказок | агент от старта до запущенной игры; любая подсказка фиксируется и обнуляет P-1 для шага, но не для прогона |
| P-2 | Документации достаточно | каждый вопрос агента, ответ на который есть в документации, — дефект документации; каждый вопрос, ответа на который нет, — карточка на документацию |
| P-3 | Ядро не зашивает первый жанр | прогоны с разными брифами (выживание / не-выживание) дают игру без правок ядра |
| P-4 | Локали не «потом» | игра, сделанная агентом, проходит `i18n-check` на 8 локалях без ручных правок |
| P-5 | Путь повторяем | второй агент по тому же брифу и по документации, дополненной после первого прогона, проходит быстрее (меньше вопросов, меньше допущений) |

## 3. Условия прогона (неизменяемая часть)

1. Чистый агент: без роли в «Ролях», без `synapse-cortex`, без Notion, без истории прошлых прогонов,
   без доступа к чатам команды.
2. Стартовый SHA `synapse` фиксируется в брифе; среда — без сети за пределами репозитория, без GPU
   и экрана (как у нас: `tools/godot/install.sh --check`).
3. Бриф выдаётся один раз и не меняется в ходе прогона.
4. Вопросы агента разрешены, но ответы даёт только Мастер **дословно из публичной документации**;
   ответ, требующего документации, которой нет, — фиксируется как пробел.
5. Прогон останавливается по факту «игра запущена и играбельна» или по лимиту времени; остановка по
   лимиту — данные, а не провал.
6. Сырой лог сессии и артефакты сохраняются; без лога прогон не считается состоявшимся.

## 4. Оракул прогона

Обязательные артефакты на одном SHA:

- `PNG` запущенной игры, который **агент сам открыл и описал**, что видит;
- вывод `validate` на своём GameSpec — `ok`;
- вывод `i18n-check` и `i18n-no-literals` — rc 0;
- журнал затруднений: шаг · что ожидал · что получил · где искал ответ · сколько времени потратил ·
  помогла ли документация;
- список явных «допущений» агента (где он догадывался, а не читал);
- карточки, выведенные из журнала (минимум одна на каждый шаг, где документация не помогла).

## 5. Метрики (для сравнения прогонов между собой)

| Метрика | Единица |
|---|---|
| Время до первой запущенной игры | минуты |
| Число вопросов | шт. |
| Из них — с ответом в документации | шт. (дефект документации) |
| Число обращений к исходникам ядра | шт. |
| Число «допущений» | шт. |
| Число шагов, где документация не помогла | шт. |

## 6. Состав первой волны

Три прогона, разные брифы, разные агенты:

1. **Пилот A — базовый:** 2D top-down выживание с крафтом (совпадает с D-010), минимальный объём.
2. **Пилот B — контрастный жанр:** не-выживание (например, пошаговая головоломка) — проверяет P-3.
3. **Пилот C — повтор A** после правок документации по итогам A и B — проверяет P-5.

Порог приёмки волны: **минимум 2 из 3 прогонов дошли до запущенной игры**, журналы разобраны,
карточки заведены. Порог не выполнен — это результат, а не повод переписать бриф.

## 7. Что запрещено

- Подсказывать по ходу прогона (кроме ответов дословно из документации).
- Менять бриф так, чтобы он совпал с тем, что агент сделал.
- Считать прогон успешным по отчёту без артефактов и лога.
- Оценивать «интересность» игры: это человеческий плейтест фазы 2, у пилота другая задача.
- Превращать пилот в производство контента: цель — сигнал о продукте.

## 8. Техническое ограничение (важное)

Сейчас транспорт выдаёт работу только зарегистрированной роли по карточке из очереди. Модель
«одноразовый агент на прогон» с этим не совместима: роль в «Ролях» получает контекст цикла, а
именно этого мы избегаем.

Поэтому **первую волну проводит Мастер вручную**: три агента, три брифа, результаты — в базу
«Обратная связь» и в карточки. Автоматизировать выдачу пилотов (отдельный режим транспорта: бриф +
одноразовый агент + приём отчёта) стоит только если волна покажет ценность. Иначе мы построим режим
ради теста, который ещё не доказал, что нужен.
