# SYN-P1 · Внешний пилот — ТЗ v1.0

**Статус:** готово к запуску по команде Мастера. Решение о подходе — D-029.
**Зачем:** проверить главное обещание продукта, которого не проверяет ни один оракул ядра:
«ИИ-автор, не знающий проекта, может сделать работающую игру, читая только публичную документацию».
**Чего здесь нет:** оценки «интересности» игры (это человеческий плейтест фазы 2), релиза игры
(для него нужен каталог — фаза 4), новых постоянных ролей (D-029).

## 1. Что проверяется

| # | Критерий | Признак выполнения |
|---|---|---|
| P-1 | Путь проходим без подсказок | агент дошёл до запущенной игры; каждая подсказка зафиксирована и обнуляет шаг, но не прогон |
| P-2 | Документации достаточно | каждый вопрос агента, ответ на который есть в документации, — дефект документации |
| P-3 | Ядро не зашивает первый жанр | прогон не-выживания даёт игру без правок `game/`, `cli/`, `schema/` |
| P-4 | Локали не «потом» | игра агента проходит `i18n-check` и `i18n-no-literals` на восьми локалях |
| P-5 | Путь улучшается | повтор брифа A после правок документации даёт меньше вопросов и меньше «допущений» |

Порог волны: **минимум 2 из 3 прогонов дошли до запущенной игры**, журналы разобраны, карточки
заведены. Порог не выполнен — это результат прогона, а не повод переписать бриф.

## 2. Условия прогона (неизменяемая часть)

1. **Чистый агент.** Без роли в базе «Роли», без `synapse-cortex`, без Notion, без истории прошлых
   прогонов, без чатов команды. Единственный вход — бриф в `docs/missions/SYN-P1-briefs.md`.
2. **Стартовый SHA** `synapse` зафиксирован в брифе; всё, что делается, — на нём.
3. **Среда** как у нас: без сети за пределами репозитория, без GPU и экрана,
   `tools/godot/install.sh --check` доступен из репозитория.
4. **Бриф выдаётся один раз** и в ходе прогона не меняется.
5. **Ответы только дословно из публичной документации.** Отвечает Мастер. Если дословно ответить
   нельзя — это пробел документации, а не подсказка; пробел фиксируется и ответ не заменяется
   объяснением «от себя».
6. **Прогон останавливается** по достижению «игра запущена и играбельна» либо по лимиту времени.
   Остановка по лимиту — данные, а не провал.
7. **Сырой лог сессии сохраняется.** Без лога прогон не считается состоявшимся.

## 3. Оракул прогона

Обязательные артефакты, все на одном SHA:

- `shot.png` запущенной игры, который **агент сам открыл и описал**, что видит;
- вывод `validate` на своём GameSpec — `ok` и код 0;
- вывод `i18n-check` и `i18n-no-literals` — код 0;
- журнал затруднений: шаг · что ожидал · что получил · где искал ответ · сколько времени потратил ·
  помогла ли документация;
- список явных «допущений» — где агент догадался, а не прочитал;
- карточки, выведенные из журнала: минимум одна на каждый шаг, где документация не помогла.

## 4. Метрики (сравнимы между прогонами)

| Метрика | Единица |
|---|---|
| Время до первой запущенной игры | минуты |
| Число вопросов | шт. |
| Из них с ответом в документации | шт. — дефекты документации |
| Обращения к исходникам ядра | шт. |
| Явные «допущения» | шт. |
| Шаги, где документация не помогла | шт. |

## 5. Первая волна

| Прогон | Бриф | Что проверяет |
|---|---|---|
| A | выживание с крафтом (D-010), минимальный объём | P-1, P-2, P-4 |
| B | пошаговая головоломка (не-выживание) | P-3 |
| C | повтор A после правок документации по A и B | P-5 |

Тексты брифов — `docs/missions/SYN-P1-briefs.md`. Брифы версионируются; изменение после старта
прогона — только новой версией с записью причины.

## 6. Техническое ограничение

Транспорт выдаёт работу только зарегистрированной роли по карточке из очереди, а «одноразовый агент»
с этим несовместим: роль в базе получает контекст цикла — ровно то, чего прогон должен избегать.
Поэтому **первую волну проводит Мастер вручную**: три агента, три брифа, отчёты — в базу «Обратная
связь», разбор — карточками. Автоматизировать выдачу пилотов (бриф + одноразовый агент + приём
отчёта) стоит только если волна покажет ценность; строить режим транспорта ради теста, который ещё
не доказал нужность, — трата цикла.

## 7. Запреты

- Подсказывать по ходу (кроме ответов дословно из документации).
- Менять бриф так, чтобы он совпал с тем, что агент сделал.
- Считать прогон успешным по отчёту без артефактов и лога.
- Оценивать «залипательность» игры.
- Превращать пилот в производство контента: цель — сигнал о продукте.
- Править `game/`, `cli/`, `schema/`, `examples/` по итогам прогона в том же ходе: выводы идут
  карточками, правки — обычным циклом.

## 8. Как закрывается

Миссия закрывается Warden по `accept` / `rework` / `master`:

- **accept** — порог волны выполнен, журналы разобраны, карточки заведены и приняты в очередь.
- **rework** — артефактов или логов не хватает, либо брифы фактически различались условиями
  (тогда прогон невалиден как сравнение).
- **master** — нужен новый агент или доступ, то есть действие Мастера.
