# SYN-2 · Фаза 1.1 — путь автора: сцена из модуля, игра с вводом, локализованный UI

Состояние: **Активна** с 2026-11-06, круг 0 (активирована Warden по D-051; цикл запускает Мастер).
Версия ТЗ 1.0. Владелец приёмки: Warden. Исполнители: `Contract Architect`, `Executor Core`,
`Locale Auditor`, `Spec Auditor` (доступ только к `Creative36711/synapse`, D-022).
Гейт: SYN-1 принята (`accept`, 2026-11-06, SHA `5b8d308`); SYN-P1 не запускается до закрытия SYN-2.
Первая очередь к выдаче: `S-1` (Contract Architect) и `S-2` (Locale Auditor) параллельно —
`docs/handoff/syn-2-card-queue.md` §2.

## 1. Зачем эта миссия

SYN-1 закрыла каркас: описание проверяется, модули разрешаются, сцена рендерится, восемь локалей
живут в диагностике. Внешний аудит и приёмка одинаково показали разрыв, который оракулом SYN-1 не
покрывался: **автор не может провести свою сцену от контракта до запуска**. `provides.scenes`
принимает смысловой ID, но `run` берёт сцену из жёстко прописанного
`game/runtime/scene_registry.gd`, поэтому модуль с валидным манифестом доходит до `validate`/`resolve`
и падает на `scene.id.unknown`. Встроенные сцены не содержат ни ввода, ни игровой логики, ни текста.

SYN-2 закрывает ровно это и ничего сверх:

1. **Сцена модуля достижима.** Манифест связывает смысловой ID с ресурсом, runtime собирает реестр
   из манифестов разрешённых модулей, `scene.id.unknown` перечисляет фактически доступные ID.
2. **Игра, а не картинка.** Мини-игра 2D top-down: управление, сбор предметов, счётчик; детерминированный
   прогон в headless с воспроизводимым вводом и отпечатком состояния мира.
3. **Определение и экземпляр разделены по-настоящему.** Два экземпляра одного определения имеют
   независимое состояние (INV-4 проверяется в рантайме, а не только отсутствием полей в схеме).
4. **Локализован игровой UI**, а не только диагностика: тексты сцен из каталогов, минимум три
   локали в контенте и восемь в каталогах.
5. **Диагностика файловых и средовых ошибок структурирована** (`code` + `params` + текст из каталога),
   а не `ENOENT`/`127` в stderr.
6. **CI покрывает то, что проверяет миссия**, а публичная документация ядра не противоречит фактам.

Вне миссии (не делать): аккаунты, каталог, публикация, покупки, хостинг, песочница, GUI-редактор,
второй жанр, воксельный мир, сохранения/загрузки, экспорт сборки, портирование валидатора на GDScript.
Правка `tools/godot/**` и `tools/godot/patches/**` запрещена; шрифты закрыты SYN-1 и не пересматриваются.

## 2. Исходная база

Репозиторий `Creative36711/synapse`, ветка `main`. Стартовый SHA фиксируется в отчёте каждой карточки;
все пункты оракула §5 выполняются на **одном итоговом SHA**. Godot — из репозитория
(`tools/godot/install.sh --check`, 4.7.2 offscreen). Зависимости — офлайн, из `vendor/`
(`tools/deps/offline-install.sh`), сеть не нужна.

## 3. Инварианты

Наследуются и проверяются заново: **INV-1…INV-10** из `SYN-1` §3 (локальность, надстройка над Godot,
смысловые ID, независимость экземпляров, граф зависимостей, диагностика поля/ожидания/факта, запрет
жанровых проверок, лицензионная рамка, отсутствие пользовательских строк вне каталогов, локаль не
меняет правила). Дополнительно:

- **INV-11. Путь автора без правок ядра.** Любая сцена, объявленная манифестом разрешённого модуля,
  достижима через `run` без изменения файлов ядра. Проверка: N-2, N-3 на модуле, добавленном в
  `examples/**`, а не в `game/**`.
- **INV-12. Локаль не меняет ни правил, ни состояния UI.** Смена локали меняет только текст;
  отпечаток мира `synapse.world-state.v1` совпадает между `en`, `de`, `ru`, `zh-Hans`. Проверка: N-5, N-7.
- **INV-13. Ни одного пользовательского текста вне каталогов, включая сцены.** Текст `Label`,
  `Button`, `tooltip_text`, заголовков окна берётся из каталога по ключу. Проверка: N-7.
- **INV-14. Диагностика не зависит от среды исполнения.** Ошибка инструмента (нет Godot, нет Node,
  нет файла) выходит машинной записью с `code`, `params` и локализованным текстом, а не сырым кодом
  оболочки. Проверка: N-8.

## 4. Защищённая зона оракула

- `tools/godot/**`, `tools/media/**`, `tools/modeling/**` — дополнять можно, ослаблять и переписывать
  нельзя; `tools/godot/patches/` не меняется (INV-2).
- `examples/**` — эталонные примеры; после появления не подгоняются под код, правка требует абзаца
  «почему» в отчёте.
- `schema/**`, `docs/contracts/**` — меняются только карточкой S-1 с записью в `docs/decisions/SYN-2.md`.
- `tests/**` — можно дополнять; ослаблять существующие проверки запрещено. Удаление проверки —
  отдельное решение Warden, а не правка карточки.

## 6. Решения, которые миссия реализует

- **D-049** — привязка смысловой сцены к ресурсу через `provides.sceneEntries` манифеста (аддитивно,
  `provides.scenes` остаётся словарём ID; путь — представление, не логика).
- **D-050** — требование Node для валидации/резолвинга: на этой фазе остаётся build-time зависимостью
  с явной документацией; портирование на GDScript — отдельная миссия фазы 2. Пункт помечен как
  продуктовый: если Мастер решит иначе, миссия не начинается до новой записи в `DECISIONS.md`.
- **D-016** (шрифты) не пересматривается: бюджет ≤ 25 МБ, `fonts.manifest.json`, NOTICE append-only.
- **D-022** — исполнители видят только `synapse`; ТЗ и очередь живут в cortex и доходят карточками.

## 7. Роли и гейты

| Шаг | Роль | Зона записи |
|---|---|---|
| Контракт сцен и определений, коды ошибок, публичная спецификация | `Contract Architect` | `schema/**`, `docs/contracts/**`, `docs/decisions/SYN-2.md` |
| Каталоги: ключи `ui.*` и новых кодов, расширение анализатора литералов | `Locale Auditor` | `locales/**`, `examples/locales/**`, `tools/i18n/**`, `tests/i18n/**` |
| Runtime: реестр сцен из манифестов, определения и экземпляры, мини-игра, UI, диагностика, CI | `Executor Core` | `game/**`, `examples/**`, `.github/workflows/**`, `AGENTS.md`, `README.md`, `package.json`, `tests/cli/**`, `tests/runtime/**` |
| Независимый аудит контракта, runtime и диагностики (N-2…N-4, N-6, N-8) | `Spec Auditor` | чтение; отчёт |
| Независимый аудит локалей и UI (N-7, N-10 в части i18n) | `Locale Auditor` | чтение; отчёт |
| Очередь, статусы, Sequence | `Coordinator` | Notion «Запросы» |
| Приёмка миссии | `Warden` | cortex (`docs/`, `DECISIONS.md`) |

Правило авторства контракта сохраняется: контракт пишет `Contract Architect`, принимает Warden,
соответствие кода контракту проверяет `Spec Auditor`.

## 8. Отчёт и артефакты

Отчёт карточки: команды, коды возврата, SHA (BASE и HEAD), ссылки на PNG в
`Arena/synapse/artifacts` (D-031), список созданных файлов, для примеров — абзац «почему».
Логи и payload — в Drive, руками не правятся. Артефакт без команды и кода возврата не принимается.

## 9. Риски и границы

- **R-12** (Godot в новой песочнице) — первой командой `install.sh --check`.
- **R-19** (реестр сцен снова захардкожен) — контролируется N-3 и INV-11.
- **R-20** (UI-текст уходит в код) — контролируется INV-13 и N-7.
- **R-21** (ложная зелень CI) — контролируется N-9: проверка должна срабатывать на PR, меняющий
  только `examples/**` или `schema/**`.
- **R-22** (расширение объёма: второй жанр, редактор, сохранения) — вне миссии; появляется только
  решением Мастера и новой миссией.
- Требует Мастера: судьба требования Node (D-050), запуск SYN-P1, любые продуктовые границы.

## 10. Критерий завершения

Закрыт каждый пункт §5, инварианты §3 проверены доказательствами, аудиты S-8 и S-9 сданы,
`DECISIONS.md` содержит фактическое решение по каждому обратимому вопросу миссии. Только после этого
Warden может вынести `accept`. Незакрытый пункт — `rework` с проверяемыми замечаниями;
`master` — только там, где без Мастера физически нельзя.
