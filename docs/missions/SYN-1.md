# SYN-1 · Фаза 1 — локальный каркас ядра

Состояние: **Принята** (`accept`, 2026-11-06, SHA `5b8d308`; активирована 2026-11-02, роли
активны).
Изменение относительно версии 1.0: добавлены INV-9, INV-10 и пункты оракула O-10…O-13
(мультиязычность, D-013…D-018).
Владелец приёмки: Warden. Исполнитель: `Executor Core` (доступ к `Creative36711/synapse`).

## 1. Цель и границы результата

Сделать так, чтобы простую игру можно было **описать декларативно, проверить и запустить
локально** — без аккаунта, без сети и без `synapse-cortex`. Это первый работающий каркас,
на котором дальше проверяются архитектурные принципы дорожной карты.

Должно стать возможным:

1. Описать игру в `GameSpec` — декларативном текстовом файле.
2. Проверить описание: валидатор объясняет ошибку так, чтобы её можно было исправить, не задавая
   вопросов.
3. Разрешить модули: манифесты с версией, зависимостями и конфликтами; циклы запрещены.
4. Запустить локальный runtime из описания и увидеть игру.
5. Разделить определение объекта, состояние экземпляра и представление.
6. Прогнать всё это одной командой и получить ненулевой код при ошибке.
7. Получить всё это **сразу на восьми локалях**: `en` по умолчанию, `ru`, `zh-Hans`, `ja`,
   `pt-BR`, `de`, `fr`, `ko` — и убедиться, что смена языка не меняет ни одного правила игры.

Вне миссии (не делать): онлайн-аккаунты, каталог, публикацию, покупки, игровой хостинг,
универсальную песочницу, редактор с GUI, второй жанр, воксельный мир, любые платные сервисы.

## 2. Исходная база

Репозиторий `Creative36711/synapse`, базовая ветка `main`. Исполнитель фиксирует стартовый SHA
в отчёте. Godot ставится из репозитория: `tools/godot/install.sh --check` (4.7.2, offscreen).

## 3. Инварианты миссии

- **INV-1.** Сборка, проверка и запуск не требуют `synapse-cortex`, сети, аккаунта и секретов.
  Проверка: выполнить оракул на чистом клоне.
- **INV-2.** Ядро — надстройка над Godot (плагин/аддон + скрипты проекта), а не форк движка.
  Проверка: `tools/godot/patches/` не меняется; сборка движка не требуется.
- **INV-3.** Логика оперирует смысловыми идентификаторами (`enemy.zombie`, `block.stone`),
  представление связывает их с ресурсами. Проверка: в коде правил нет имён файлов ассетов.
- **INV-4.** Определение не хранит изменяемое состояние экземпляра. Проверка: два экземпляра
  одного определения в рантайме имеют независимое состояние.
- **INV-5.** Зависимости модулей проверяются как граф; цикл — ошибка, а не предупреждение.
- **INV-6.** Ошибка валидатора называет поле, ожидание и фактическое значение. Проверка: разбор
  десяти намеренно сломанных описаний — по тексту понятно, что править.
- **INV-7.** Никаких проверок вида `if genre == ...` в ядре.
- **INV-8.** `LICENSE` (MIT), `NOTICE` с фактическими зависимостями и раздел README про
  лицензионную модель присутствуют и не противоречат друг другу.
- **INV-9.** Ни одной пользовательской строки вне каталогов локализации. Ошибка валидатора —
  это `code` + параметры; текст ошибки берётся из каталога. Проверка: `i18n-no-literals` и
  `i18n-check` зелёные, `VALIDATION_ERROR` на `ja` содержит то же имя поля и значение, что на `en`.
- **INV-10.** Смена локали не влияет на состояние мира и на результат проверки. Проверка: `run`
  на `en` и на `de` даёт одинаковый итоговый отпечаток состояния за 120 кадров.

## 4. Защищённая зона оракула

- `tools/godot/**`, `tools/media/**`, `tools/modeling/**` — существующие инструменты и их
  self-tests. Дополнять можно, ослаблять и переписывать — нельзя.
- `examples/**` — эталонные примеры для оракула: после появления их нельзя «подгонять» под код;
  изменение примера требует объяснения в отчёте.
- Схемы и контракты (`schema/**`, `docs/contracts/**`) — изменение только с фиксацией в отчёте.

## 5. Финальный оракул

Выполняется из корня `synapse` на чистом клоне; результаты — с кодом возврата и артефактами.

| # | Команда | Ожидается |
|---|---|---|
| O-1 | `tools/godot/install.sh --check` | код 0; `shot_1.png` и `shot_2.png` существуют; агент **сам** их открыл и описал (текстурный куб, небо, тень, текст; во втором кадре куб повёрнут) |
| O-2 | `godot --headless --path game --quit` | код 0, в выводе нет ошибок парсинга GDScript |
| O-3 | `godot --headless --path game --script res://cli/synapse.gd -- validate examples/minimal.game.yaml` | код 0, машиночитаемый результат `ok` |
| O-4 | то же с `examples/broken.game.yaml` | код ≠ 0, в выводе есть имя поля, ожидание и фактическое значение |
| O-5 | то же с `examples/cycle.game.yaml` | код ≠ 0, вывод называет цикл вида `a → b → a` |
| O-6 | `… -- resolve examples/minimal.game.yaml` | код 0, печатает порядок загрузки модулей, детерминированный между запусками |
| O-7 | `… -- run examples/minimal.game.yaml --frames 120 --shot /tmp/syn1/final.png` | код 0, PNG создан; агент открыл его и описал, что видно |
| O-8 | `grep -rn "genre ==" game/ cli/` | пусто |
| O-9 | Наличие `LICENSE`, `NOTICE`, раздела о лицензии в `README.md` | есть; в README явно сказано «MIT для ядра» и что экспорт игры свободен |
| O-10 | `… -- validate examples/broken.game.yaml --lang ja` и `--lang de` | код ≠ 0; в выводе тот же `code` и те же `path`/`actual`, что и на `en`, текст сообщения — на запрошенном языке. Присланные тексты не пустые |
| O-11 | `i18n-check` и `i18n-no-literals` из корня `synapse` | код 0; `en` — 100 % ключей; остальные семь — ≥ 95 % ключей CLI/валидатора; литералов вне каталогов нет |
| O-12 | `… -- run examples/minimal.game.yaml --lang de --frames 120 --state /tmp/syn1/de.json` и то же с `--lang en` | код 0; файлы состояния совпадают по содержимому мира (INV-10) |
| O-13 | Рендер-тест шрифтов: запуск примера на `ja`, `zh_CN`, `ko` со скриншотом | PNG создан; агент открыл его и убедился, что нет тофу-глифов (пустых квадратов) |

Вспомогательные проверки (быстрые, для карточек): `godot --headless --path game --import`,
юнит-прогоны валидатора на фикстурах, повторный запуск O-3…O-7 дважды подряд (идемпотентность),
`i18n-coverage` / `i18n-placeholders` / `i18n-pseudo` при каждой правке каталогов.

`not run`, тайм-аут и «работает локально у меня» не равны pass. Итоговый SHA фиксируется один
и тот же для всех пунктов.

## 6. Роли, зоны и гейты

- `Executor Core` — пишет в `synapse` в пределах `Scope` карточки, PR в `main`.
- `Contract Architect` — владеет контрактами: схема `GameSpec`, формат манифеста модуля, коды ошибок
  (D-020). Пишет `docs/contracts/**` и ADR; фичи не пишет.
- `Spec Auditor` — независимо проверяет O-4, O-5, O-8 и содержание ошибок валидатора; код не правит.
- `Locale Auditor` — независимо проверяет O-10…O-13 и глоссарий; переводов не пишет.
- `Coordinator` — режет миссию на карточки, ведёт порядок, собирает «Итог».
- `Warden` — принимает миссию по этому оракулу.
- `Executor Platform` — в миссии не участвует; при необходимости правок транспорта это отдельная
  миссия.

**Все семь ролей активны с 2026-11-02**, поэтому карточки идут владельцам зон: `docs/contracts/**`,
`schema/**` и ADR — `Contract Architect` (K-2), `locales/**`, `i18n/**`, `GLOSSARY.md` — `Locale Auditor`
(K-6, K-7, K-10). Правило «автор контракта не единственный его проверяющий» не меняется: контракт
принимает Warden, соответствие кода контрактам проверяет `Spec Auditor` (O-4, O-5, O-8), локали —
`Locale Auditor` (O-10…O-13). Если роль недоступна в конкретном ходе, карточка не переписывается
на другого исполнителя молча: Coordinator помечает её `Blocked` и сообщает Warden.

## 7. Артефакты и отчёты

- Отчёт исполнителя: команды, коды возврата, SHA, ссылки на скриншоты, список созданных файлов.
- Журнал решений карточки (если нужен): `docs/decisions/SYN-1.md` в `synapse`.
- Черновики `LICENSE`/`NOTICE` для переноса: `docs/handoff/core-license-notice.md` в cortex.
- Перенос контрактов и i18n-политики в `synapse`: `docs/handoff/core-contracts-i18n.md` в cortex.
- Очередь карточек для Coordinator: `docs/handoff/syn-1-card-queue.md` в cortex (K-1…K-13);
  Notion-копия для исполнителей — дочерняя страница миссии «SYN-1 · очередь карточек».

**Внимание по доступам (D-022).** Исполнитель миссии видит только `synapse`. Требования из
`docs/I18N.md`, `docs/DECISIONS.md` и этого ТЗ попадают к нему карточкой и страницей «Миссии»
в Notion. Ссылаться в карточке на файл в cortex нельзя — исполнитель его не откроет.

## 8. Риски и открытые вопросы

- **R-01** (закрытый код в сборке) — контролируется INV-1.
- **R-02** (зашитый жанр) — контролируется INV-7 и фазой 3.
- **R-16** (CJK-шрифты: размер и тофу) — контролируется O-13 и бюджетом ≤ 25 МБ.
- **R-17** (дрейф переводов) — контролируется O-11 и порогом покрытия.
- **R-18** (локаль меняет правила) — контролируется INV-10 и O-12.
- **R-12** (Godot в новой песочнице) — первым делом `install.sh --check`.
- Открытый вопрос: формат `GameSpec` (YAML или JSON). Предложение — YAML как более
  человекописуемый; решение фиксируется в `DECISIONS.md` при первом коммите схемы.
- Открытый вопрос: пример локализуем на `en` + `ru` + `zh-Hans` (доказательство конвейера) или
  сразу на все восемь. Предложение — три языка в миссии, остальные проверяются каталогами CLI
  и рендер-тестом шрифтов; полный контент — в фазе 2.
- Открытый вопрос: где живёт исполняемая игровая сборка (`game/`) — в `synapse` как эталонный
  проект или генерируется из `GameSpec`. Предложение — эталонный проект в репозитории до фазы 2.

## 9. Критерий завершения

Каждый пункт §5 закрыт доказательством (команда, код возврата, артефакт, SHA), инварианты §3
проверены, `LICENSE`/`NOTICE`/README актуальны. Только после этого Warden может вынести `accept`.
