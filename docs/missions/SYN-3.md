# SYN-3 · Фаза 1.2 — измеримость: инвариант, который нельзя обойти молча

Состояние: **Активна** с 2026-11-08 (активирована Warden по D-057; цикл запускает Мастер).
Версия ТЗ 1.1 (1.1 — поправка от 2026-11-08 по замечаниям Мастера: два среза отпечатка,
Scope, исполнимые пункты, цифра `i18n-check` 30; D-058 в редакции с поправкой, D-062). Владелец приёмки: Warden. Исполнители: `Contract Architect`, `Executor Core`,
`Locale Auditor`, `Spec Auditor` (доступ только к `Creative36711/synapse`, D-022).
Гейт: SYN-2 принята (`accept`, круг 1, SHA `6cff12a`); SYN-P1 не запускается до приёмки SYN-3.
Очередь к выдаче: `docs/handoff/syn-3-card-queue.md` — B1 и B5 параллельно.

## 1. Зачем эта миссия

SYN-1 и SYN-2 дали работающий каркас: описание проверяется, модули разрешаются, сцена модуля
достижима, каталоги живут в восьми локалях, диагностика машинная. Приёмка SYN-2 пройдена по всему
оракулу — и одновременно показала, что **два ключевых инварианта держатся на измерении, которое
их не различает**:

- отпечаток мира `synapse.world-state.v1` не содержит ни локали, ни текста узла, ни номера кадра —
  два прогона с картинками, различающимися на 4100 пикселей, дают побайтово равный отпечаток;
- анализатор литералов `i18n-no-literals` не видит многострочный литерал и конкатенацию, то есть
  пользовательский текст возвращается в код тремя строками при зелёной проверке.

Оба дефекта — не «баги фичи», а **дефекты доказательства**: пока они есть, зелёная приёмка
неотличима от регрессии, и любая следующая миссия строится на доверии, которого нет. SYN-3
закрывает ровно этот разрыв и ничего сверх.

Что делается:

1. **Отпечаток становится снимком наблюдаемого.** В него входят локаль, номер кадра, текст и
   подсказки узлов, видимость — с явным перечнем полей (`fingerprintScope`), чтобы «равенство»
   всегда значило «равенство перечисленного». v1 остаётся читаемым и в доказательствах не участвует.
2. **Ввод становится вводом.** Арена принимает реальные `InputEvent`, кнопки подключены; сценарий
   ввода остаётся детерминированным и воспроизводимым.
3. **Код отказа не подменяется.** Ошибка записи состояния, ошибка файла действий и отсутствие
   движка — три разных кода; путь в `params` не искажается при сборке argv вложенного запуска.
4. **Проверки fail-closed.** Недоступен парсер — проверка литералов падает. Шаблон тестов не
   совпал ни с одним тестом — шаг CI падает. Нет движка — падает диагностика, а не тишина.
5. **Все восемь локалей в игровом контенте**, а не только в каталогах (вторая волна, C1).
6. **Публичная документация равна измеренному**: README и контракты описывают то, что проверяется,
   включая коды `ref.unresolved` и `actions.file.missing`.

Вне миссии (не делать): аккаунты, каталог, публикация, покупки, хостинг, песочница, GUI-редактор,
второй жанр, сохранения/загрузки, экспорт сборки, мультиплеер, Windows/macOS/мобильные сборки,
порт валидатора на GDScript (D-050). Правка `tools/godot/**` и `tools/godot/patches/**` запрещена;
шрифты закрыты SYN-1 (D-016) и не пересматриваются.

## 2. Исходная база

Репозиторий `Creative36711/synapse`, ветка `main`, стартовый SHA — `6cff12a` (приёмка SYN-2).
Стартовый SHA фиксируется в каждой карточке; все пункты §5 выполняются на **одном итоговом SHA**.
Движок — `tools/godot/install.sh` (версия 4.7.2), артефакты — `Arena/synapse/artifacts` (D-031).
Среда: 2 ядра, 3 ГБ, GPU нет; сеть по белому списку.

## 3. Инварианты

Наследуются и проверяются заново **INV-1…INV-14** (`SYN-1` §3, `SYN-2` §3) с уточнением области,
введённым D-057: INV-12 и INV-13 считаются выполненными для объявленного набора входов и **не**
считаются защищёнными от обхода. Дополнительно:

- **INV-12 (уточнение D-058).** Локаль не меняет ни правил, ни состояния мира: срез отпечатка
  `rules` (`frame`, геометрия, `visible`, состояние сущностей — без локали и без текста) обязан быть
  побайтово равен между всеми восемью локалями. Замена этой проверки на «оба прогона завершились
  кодом 0» — ослабление.
- **INV-15. Отпечаток состоит из двух объявленных срезов, и равенство значит ровно то, что
  перечислено в срезе.** Один артефакт `synapse.world-state.v2` несёт `rules` (без локали и текста),
  `presentation` (`locale`, `text`, `tooltip_text`, `title`) и `artifact` (полный хеш — только для
  идентичности, в доказательстве INV-12 не участвует). Поля перечислены в `fingerprintScope`.
  `rules` равны между локалями, `presentation` — различаются, причём не только полем `locale`:
  между `en` и `de` обязан различаться хотя бы один из `text`/`tooltip_text`/`title`.
  Проверка: V-2, обе негативные фикстуры обязательны.
- **INV-16. Инструмент проверки не имеет «тихого» режима.** Если парсер или движок недоступен,
  проверка завершается кодом ≠ 0 с машинной записью, а не сообщением «0 находок». Проверка: V-5, V-9.
- **INV-17. Код ошибки называет причину.** `runtime.engine.missing` возвращается только когда
  движка нет; ошибка записи состояния — `cli.run.state.write_failed`, ошибка файла действий —
  `actions.file.missing`; `params.path` равен пути, который передал автор. Проверка: V-4.
- **INV-18. Ввод — событие, а не массив.** Арена реагирует на `InputEvent` и на нажатие кнопок;
  одинаковый сценарий событий дважды подряд даёт одинаковый отпечаток. Проверка: V-3.

## 4. Защищённая зона оракула

- `tools/godot/**`, `tools/media/**`, `tools/modeling/**` — дополнять можно, ослаблять и
  переписывать нельзя; `tools/godot/patches/` не меняется (INV-2).
- `examples/**` — эталонные примеры; после появления не подгоняются под код, правка требует абзаца
  «почему» в отчёте.
- `schema/**`, `docs/contracts/**` — меняются только карточкой B1 с записью в
  `docs/decisions/SYN-3.md`.
- `tests/**` — можно дополнять; ослаблять существующие проверки запрещено. Удаление проверки —
  отдельное решение Warden.
- `synapse.world-state.v1` остаётся **схемой** и историческим артефактом: документы v1 остаются
  валидными, но runtime пишет только v2, флаг `--state-format` в этой миссии не вводится (D-058).

`N-` миссий SYN-1/SYN-2: те пункты остаются в силе как регресс и выполняются тоже.

## 6. Решения, которые миссия реализует

- **D-057** — фаза 1 принята с ограниченной областью действия инвариантов (INV-12/INV-13 не
  объявляются защищёнными до SYN-3).
- **D-058** (в редакции с поправкой 2026-11-08) — отпечаток мира v2 из двух срезов `rules` и
  `presentation` с двумя хешами и полным хешем `artifact`; v1 читается и в доказательствах не
  участвует; две обязательные негативные фикстуры. v2 — формат вывода по умолчанию, три assert на
  v1 в `tests/cli/run.test.mjs` переводятся на v2 явно.
- **D-062** — оракул исполним на том, что есть: `--root` для анализатора и временные проекты,
  `tests/fixtures/**` только под сценарий ввода, машинное сравнение PNG через ImageMagick,
  базовая цифра `i18n-check` 8×30; Scope карточки обязан покрывать все пути её «Сделано, когда».
- **D-063** — технологический roadmap (`docs/handoff/technology-roadmap.md`), MCP не внедряем,
  роль `Transport Maintainer` вне очереди.
- **D-064** — `ROADMAP.md` и `METRICS.md` ведутся в публичном `synapse`.
- **D-059** — анализатор литералов fail-closed на настоящем парсере (`gdtoolkit`/`gdparse`) в
  изолированном venv; самописный токенизатор в роли «доказательства» не используется.
- **D-060** — код ошибки называет причину; подмена класса отказа запрещена (INV-17).
- **D-061** — игровой контент переводится на все восемь локалей; порог для ключей `game.*` — 100 %
  к концу миссии.
- **D-049**, **D-050**, **D-016**, **D-022** не пересматриваются.

## 8. Отчёт и артефакты

Отчёт карточки: команды, коды возврата, SHA (BASE и HEAD), версия отпечатка, ссылки на PNG в
`Arena/synapse/artifacts` (D-031), список созданных файлов, для примеров — абзац «почему».
Логи и payload — в Drive, руками не правятся. Артефакт без команды и кода возврата не принимается.
Артефакт отпечатка v1 в доказательствах не принимается (см. §4).

## 9. Риски и границы

- **R-23** (несовместимость отпечатков) — контролируется V-2/V-11: сравнение только внутри версии
  и только по объявленному срезу; версия и срез указаны в каждом отчёте.
- **R-29** (срез `rules` снова станет слепым, если из него уберут геометрию) — контролируется
  негативной фикстурой (а) V-2: сцена с геометрией, зависящей от локали, обязана дать разные `rules`.
- **R-30** (визуальная проверка вернётся к «агент посмотрел») — контролируется C1: сравнение
  `compare -metric AE` с эталоном и diff-артефакт обязательны, описание глазами — дополнение.
- **R-24** (Python-зависимость в сборке Node) — контролируется V-5: venv вне `package.json`,
  fail-closed без парсера.
- **R-25** (реальный ввод ломает детерминизм) — контролируется V-3: одинаковый сценарий событий
  даёт одинаковый отпечаток.
- **R-26** (2 ядра / 3 ГБ) — одна карточка в работе; не более четырёх процессов Godot подряд.
- **R-27** (ложная зелень CI вернулась иначе) — контролируется V-9.
- **R-28** (расширение объёма под видом «заодно починим») — вне миссии по §1; новое — только
  решением Мастера и новой миссией.
- Требует Мастера: формат отпечатка (H-1). Остальное решается Warden обратимо, с «Допущение:».

## 10. Критерий завершения

Закрыт каждый пункт §5, инварианты §3 проверены доказательствами на одном SHA, аудит B7 сдан,
`DECISIONS.md` содержит фактическое решение по каждому обратимому вопросу миссии. Только после
этого Warden может вынести `accept`. Незакрытый пункт — `rework` с проверяемыми замечаниями;
`master` — только там, где без Мастера физически нельзя.
