# SYN-P1 · Брифы первой волны (v1.0)

Бриф — это единственный вход агента. Он же оракул: подгонять его под результат нельзя. Копируется
Мастером целиком, без сокращений и без добавления пояснений.

## Бриф A · «Выживание с крафтом»

(Стартовый SHA: `__FILL_AT_START__`.)

Ты — ИИ-разработчик игр. Тебе нужно сделать небольшую 2D-игру с видом сверху: выживание с крафтом
(собираешь ресурсы, крафтишь предметы, переживаешь ночь). Движок и конструктор — в этом репозитории:
`Creative36711/synapse`. Документация — в нём же.

Правила:

1. Читай репозиторий и его документацию. Больше источников у тебя нет.
2. Не меняй `tools/`, `schema/`, `docs/contracts/` и не переписывай ядро — ты автор игры, а не
   разработчик движка. Если ядро не даёт сделать что-то штатно, так и запиши.
3. Действуй сам. Если застрял больше 10 минут — пиши в журнал, где именно, и продолжай по
   ближайшему разумному пути; так и помечай: «допущение».
4. Вопросы разрешены, но ответ ты получишь только дословной цитатой из документации. Если дословно
   ответить нельзя — это дефект документации, а не повод получить объяснение.
5. Веди журнал: шаг · что ожидал · что получил · где искал ответ · время · помогла ли документация.

Результат:

- работающая игра, запускаемая по инструкции из репозитория;
- скриншот, который ты сам открыл и описал;
- `validate` на твоём GameSpec — `ok`;
- `i18n-check` и `i18n-no-literals` — зелёные на восьми локалях;
- журнал затруднений и список допущений;
- список «здесь документация не помогла» — по пункту на каждый случай.

(Стартовый SHA: `__FILL_AT_START__` — уже после PR с правками документации по итогам A и B.)

это тоже результат, и он важнее, чем «прошло».

## Как считать, что прогон состоялся

- есть стартовый SHA в брифе и в отчёте;
- есть сырой лог сессии;
- есть все артефакты раздела «Результат»;
- есть журнал затруднений с временами;
- есть карточки, выведенные из журнала (или явная запись «затруднений не было», если их правда нет).
