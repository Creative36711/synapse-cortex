# Drive Gateway: пошаговая настройка

Как зарегистрировать проект `synapse` в шлюзе. Инструкция написана по фактическому коду
`tools/script-cat/drive-gateway.gs` (версия 1.6), а не по памяти.

**Может сделать только Мастер.** Warden не может выполнить эти шаги — см. раздел 6.

---

| Проверка | Результат |
|---|---|
| Папок `Arena` в корне Диска | **ровно одна** — `15qaNDaYhPjv8YmHO-Nf_603PlynM6oUn` ✓ |
| Папки `synapse` внутри `Arena` | **нет** ✓ |
| Проект Apps Script `Gateway` | есть — `1iyOXVe73wJx1lOzZ5xTwp110k5G3pnth_adQ2UBdWhxaSUdnYrfJuO55` ✓ |

Обе проверки критичны: шлюз **откажется** работать, если папок `Arena` несколько,
и откажется регистрировать проект, если `Arena/synapse` уже существует. Сейчас всё чисто.

**Не трогать:** существующие `Arena/logs` и `Arena/payloads` — это наследие прежней
(не проектной) раскладки. Новый проект получит **свои** `Arena/synapse/logs` и
`Arena/synapse/payloads`. Это разные папки, они не мешают друг другу.

## 1. Что нужно до начала

## 2. Обновить код шлюза

### 2.1 Открыть проект Apps Script

Проект `Gateway` лежит в папке `Arena` на Диске. Его идентификатор:

```
1iyOXVe73wJx1lOzZ5xTwp110k5G3pnth_adQ2UBdWhxaSUdnYrfJuO55
```

Открыть одной из ссылок (нужно быть авторизованным в том же Google-аккаунте):

- <https://script.google.com/home/projects/1iyOXVe73wJx1lOzZ5xTwp110k5G3pnth_adQ2UBdWhxaSUdnYrfJuO55/edit>
- <https://script.google.com/d/1iyOXVe73wJx1lOzZ5xTwp110k5G3pnth_adQ2UBdWhxaSUdnYrfJuO55/edit>

Если ссылка не открывается — зайти на <https://script.google.com/home> и найти проект `Gateway`
в списке.

### 2.2 Сохранить точку отката

`Файл → Управление версиями → Сохранить новую версию`. Если что-то пойдёт не так,
будет к чему вернуться.

### 2.3 Скопировать код шлюза

**Откуда.** Файл в этом репозитории:

<https://github.com/Creative36711/synapse-cortex/blob/main/tools/script-cat/drive-gateway.gs>

Как скопировать — репозиторий закрытый, поэтому нужен браузер с выполненным входом в GitHub:

1. Открыть ссылку выше.
2. В правом верхнем углу блока кода нажать **Raw** — откроется чистый текст
   с временным токеном доступа.
3. `Ctrl+A`, затем `Ctrl+C`.

Если кнопка **Raw** не срабатывает — нажать иконку копирования (два листа) в том же правом
верхнем углу блока кода.

**Куда.** В редакторе Apps Script:

1. В списке файлов слева выбрать файл с кодом — обычно он называется `Код.gs`.
2. `Ctrl+A` внутри редактора, затем `Ctrl+V` — вставить поверх.
3. `Ctrl+S` (или значок дискеты) — сохранить.

**Проверить:** в списке файлов слева **не должно остаться других `.gs`-файлов** со старым кодом
шлюза. Apps Script склеивает все `.gs`-файлы в одну область видимости, и одинаковые имена
функций в разных файлах приводят к непредсказуемому поведению. Если такие файлы есть —
удалить их (`⋮` справа от имени файла → `Удалить`), предварительно сохранив версию по шагу 2.2.

### 2.4 Скопировать манифест

**Откуда.** Файл в этом репозитории:

<https://github.com/Creative36711/synapse-cortex/blob/main/tools/script-cat/appsscript.json>

**Содержимое — можно скопировать прямо отсюда:**

```json
{
  "timeZone": "Europe/Moscow",
  "exceptionLogging": "STACKDRIVER",
  "runtimeVersion": "V8",
  "oauthScopes": [
    "https://www.googleapis.com/auth/drive",
    "https://www.googleapis.com/auth/script.storage"
  ]

```

**Куда.** Файл манифеста по умолчанию скрыт:

1. `Настройки проекта` (шестерёнка в левой панели).
2. Поставить галочку **«Показывать файл манифеста appsscript.json»**.
3. Вернуться в редактор (`<>` значок). В списке файлов появится `appsscript.json`.
4. Открыть его, `Ctrl+A`, `Ctrl+V`, `Ctrl+S`.

**Прочитать перед согласием.** Манифест запрашивает `…/auth/drive` — это широкий доступ
ко всему Диску. Убедиться, что это твой аккаунт и именно этот код, прежде чем разрешать.

## 3. Задать настройки скрипта

Путь: `Настройки проекта` (шестерёнка) → прокрутить в самый низ → блок
**«Свойства скрипта»** → кнопка **«Изменить свойства скрипта»** → **«Добавить свойство»**.

Добавить два свойства:

| Свойство | Значение |
|---|---|
| `CF_SETUP_PROJECT_ID` | UUID профиля ScriptCat из шага 1 |
| `CF_SETUP_PROJECT_FOLDER` | `synapse` |

После ввода обоих — **«Сохранить свойства скрипта»**. Без этого нажатия значения не сохранятся.

**Откуда взять UUID профиля.** В ScriptCat: `⚙ Подключения → Управление проектами`, создать
профиль, затем нажать «Открыть выбранный проект». UUID показывается в карточке профиля —
его нужно скопировать до перехода к этому шагу.

**Ограничения, которые проверяет код:**

- UUID — строго в формате `8-4-4-4-12` шестнадцатеричных цифр, регистр не важен.
- Имя папки — только `a-z`, `0-9`, точка, подчёркивание, дефис; от 1 до 51 символа;
  начинается с буквы или цифры; **не** `logs` и **не** `payloads`; без `..`.

## 4. Запустить регистрацию — один раз

В редакторе Apps Script:

1. В выпадающем списке функций **вверху по центру** (рядом с кнопками «Выполнить» и «Отладка»)
   выбрать **`setupProjectGateway`**. Если её нет в списке — код не сохранился, вернуться к шагу 2.3.
2. Нажать **«Выполнить»**.
3. Google покажет окно **«Требуется авторизация»** → «Проверить разрешения» → выбрать свой
   аккаунт → «Дополнительные сведения» → «Разрешить». Окно пугающее, но это твой собственный
   скрипт, непроверенным он называется потому, что не проходил проверку Google.
4. Дождаться завершения — вверху появится «Выполнение завершено».

**Что произойдёт:**

```
Arena/synapse/          ← создаётся
├── logs/               ← создаётся
└── payloads/           ← создаётся
```

Ключ появляется в двух местах:

- `Просмотр → Журналы` (или `Выполнения` в новой версии редактора) — строка вида:
  ```
  Project <uuid> · Arena/synapse · key (keep private): <ключ проекта>
  ```
- результат выполнения функции — в панели под редактором, если она открыта:
  ```json
  { "projectId": "<uuid>", "folder": "synapse", "key": "<ключ проекта>" }
  ```

**Скопировать `<ключ проекта>`** — он понадобится в шаге 6.

Если окно журналов пустое — обновить страницу и убедиться, что фильтр стоит на
«Все выполнения», а не только на «Ошибки».

**Это НЕ общий ключ шлюза.** Общий `CF_GATEWAY_KEY` копировать **запрещено** — он даёт доступ
ко всем проектам сразу. Нужен именно ключ проекта из этой строки.

## 5. Если функция выдала ошибку

| Текст ошибки | Причина | Что делать |
|---|---|---|
| `CF_SETUP_PROJECT_ID должен быть UUID` | опечатка в UUID профиля | сверить UUID, скопировать заново |
| `CF_SETUP_PROJECT_FOLDER должен быть безопасным…` | недопустимое имя папки | использовать `synapse` |
| `Проект уже зарегистрирован` | этот UUID уже в реестре | ключ не меняется; если нужен новый — другой профиль |
| `Это имя папки уже занято проектом` | имя `synapse` занято | другое имя или разобрать реестр |
| `В корне несколько папок Arena` | дубликаты `Arena` | разобрать вручную, оставить одну |
| `Папка проекта уже существует` | `Arena/synapse` создана вручную | **не удалять папки вслепую** — сначала проверить реестр |

**Функция не идемпотентна.** При сбое она может оставить созданные папки. Не запускать повторно
вслепую — сначала посмотреть реестр (`CF_GATEWAY_PROJECTS_V1`) и содержимое `Arena`.

## 6. Почему это не может сделать Warden

Три причины, каждая достаточная:

1. **Техническая.** `setupProjectGateway()` — функция Google Apps Script, которая выполняется
   через `DriveApp` от имени владельца аккаунта. Доступ запускать её в твоём Apps Script есть
   только у тебя. Коннектор Google Drive не умеет выполнять Apps Script.
2. **Секрет.** Функция создаёт ключ проекта и печатает его в журнал Apps Script. Ключ — секрет;
   по регламенту его вводит владелец, я не запрашиваю и не храню такие значения.
3. **Регламент.** Регистрация проекта в шлюзе — действие только владельца, операция
   неидемпотентна и необратима.

## 7. Развернуть веб-приложение

1. Нажать синюю кнопку **«Развернуть»** в правом верхнем углу → **«Новое развертывание»**.
2. Слева от «Выбрать тип» нажать **шестерёнку** → выбрать **«Веб-приложение»**.
3. Заполнить:
   - **Описание:** например `Relay gateway 1.6 · synapse`.
   - **Выполнять как:** **Я** (владелец аккаунта).
   - **У кого есть доступ:** **У кого есть ссылка**.
4. Нажать **«Развернуть»**.
5. Google снова запросит авторизацию — разрешить.
6. Скопировать **URL веб-приложения** — он оканчивается на `/exec`.

> Одного сохранения кода **недостаточно**. Пока не создано **новое** развертывание,
> шлюз продолжает работать на старом коде.

**Как потом понять, что развёрнута нужная версия:** `Развернуть → Управление развертываниями` —
в списке активных должно быть веб-приложение с описанием из шага 3.

## 9. После регистрации — что нельзя делать

`projectLayout_()` проверяет расположение и имена папок **при каждом запросе**. Если что-то
сдвинуть, шлюз перестанет работать и вернёт:

```
Папки проекта перемещены или переименованы
```

Поэтому после регистрации:

- не переименовывать `Arena`, `Arena/synapse`, `logs`, `payloads`;
- не перемещать эти папки;
- **не складывать в `Arena/synapse` ничего своего** — это служебное хранилище шлюза,
  туда пишут журналы ходов и полезные нагрузки.

## 10. Про папку `Synapse` в корне Диска

Папка `Synapse` в корне Диска (`1frm1IMUrRbDYH3fLFLvTipcUFiCMWSTZ`) с подпапками
`docs`, `reports`, `decisions`, `assets` — **это другое, и переносить её никуда не нужно.**

| Папка | Кто создаёт | Что там | Кто пишет |
|---|---|---|---|
| `Arena/synapse/` | **шлюз**, при регистрации | `logs`, `payloads` — служжебные данные | только шлюз |
| `Synapse/` | Warden | документы, отчёты, решения, артефакты | люди и агенты |

Они не мешают друг другу: одна внутри `Arena`, другая в корне, имена разные.

**Опасность, которую нужно обойти:** если переместить `Synapse` внутрь `Arena` и переименовать
в `synapse` **до** регистрации, шлюз откажется работать — он не присоединяет существующие папки.
Поэтому папку документов не трогаем вообще.
