# SYN-2 · очередь карточек для Coordinator

Передача от Warden, 2026-11-06. Очередь режет миссию SYN-2 (`docs/missions/SYN-2.md`, ТЗ 1.0)
на карточки, готовые к постановке по одной. ТЗ — источник требований, этот документ — источник
**порядка**. При расхождении выигрывает ТЗ, расхождение идёт в «Замечания» миссии.

Notion-копия для исполнителей: дочерняя страница миссии SYN-2 (создаётся Coordinator вместе
с первой карточкой; тексты копируются целиком, ссылок на cortex в карточках быть не может, D-022).

**Состав ролей:** все семь ролей базы «Роли» `Активна` и покрывают миссию — новых ролей не требуется.
Зоны: `Contract Architect` и `Executor Core` и `Locale Auditor` — `synapse`; `Spec Auditor`,
`Coordinator`, `Warden`, `Executor Platform` — `synapse-cortex` (`Executor Platform` в SYN-2 не участвует).

## 1. Правила постановки

1. Одна карточка — одна зона записи. Пересечение зон запрещено; нужно две — две карточки и зависимость.
2. В карточке обязательно: цель, `Scope` (пути в `synapse`), «Сделано, когда» (пункты N-1…N-10
   и INV-1…INV-14), запреты, форма отчёта.
3. Карточка закрывается доказательством: команда, код возврата, артефакт, SHA. «not run», тайм-аут,
   «локально работает» и зелёный CI без проверки на нужном пути — не pass.
4. Контракты (`schema/**`, `docs/contracts/**`) меняются только S-1. Молчаливое изменение контракта
   в другой карточке — возврат.
5. `examples/**` после появления не подгоняются под код; правка примера требует абзаца «почему».
6. Ветки и PR — в `main` репозитория `synapse`. Один PR на карточку или на пару связанных.
7. Круг инкрементируется при возврате. После третьего возврата одной карточки Coordinator
   останавливает очередь и передаёт решение Warden.
8. Ни одна карточка не ослабляет проверки SYN-1: `test:contracts` 82, `test:validation` 16,
   `test:modules` 12, `test:i18n` 18, `test:deps` 8, `i18n-check` 8×17/17 и `tests/cli` 11 остаются
   зелёными; уменьшение чисел — повод для возврата.

## 3. Карточки

### S-1 · Контракт сборки: сцены модуля и определения объектов
- **Исполнитель:** `Contract Architect`. **Зависимостей нет.** Sequence 10.1.
- **Scope:** `schema/**`, `docs/contracts/**`, `docs/decisions/SYN-2.md`.
- **Цель:** дать манифесту законный способ связать смысловой ID сцены с ресурсом и зафиксировать
  разделение определения и экземпляра до кода.
- **Содержание:**
  1. `provides.sceneEntries` — массив `{id, resource}`, аддитивно к `provides.scenes`:
     `id` обязан входить в `provides.scenes`; `resource` — только `res://…tscn`, без `..` и абсолютных
     путей; дубль `id` внутри манифеста и между модулями — ошибка; отсутствующий `resource` — ошибка
     валидатора (проверка существования файла без сети и без импорта движка).
  2. `entities` в GameSpec — `id` + `properties` (только примитивы), без полей состояния экземпляра;
     `id` по грамматике смысловых ID; ключи локализации не дублируют состояния.
  3. Реестр кодов: `scene.entry.unknown`, `scene.resource.missing`, `scene.duplicate`,
     `spec.file.missing`, `runtime.engine.missing`, `cli.dependency.node_missing` — с `params`,
     `catalogKey`, строками в `docs/contracts/errors.md` и примерами в `cases.json`.
  4. Публичная спецификация для автора: `docs/contracts/scene-binding.md` — как объявить сцену,
     как её увидит `run`, что означает каждая ошибка. Без внутренней кухни (роли, очередь, cortex).
  5. Приведение статуса в `docs/contracts/README.md` к факту: формат принят (решение уже
     ратифицировано), «черновик формата» убрать; ссылка на решение — в тексте, не на cortex-файл.
- **Сделано, когда:** `npm run check:contracts` ≥ 82 без fail и покрывает новые поля и коды; у каждого
  нового кода есть валидный и невалидный пример; в `docs/decisions/SYN-2.md` записаны решения миссии
  по формату `sceneEntries` и `entities` («неясно / решил / откат»); тексты `docs/contracts/**` не
  ссылаются на cortex.
- **Запреты:** писать реализацию валидатора, резолвера или рантайма; менять существующие поля
  `provides.scenes` и `entry.scene`; вводить текст ошибки строкой в контракт.

### S-2 · Каталоги: ключи UI и новых диагностик на восемь локалей
- **Исполнитель:** `Locale Auditor`. **Зависимостей нет** (ключи согласуются с S-1 по коду ошибки).
  Sequence 10.2.
- **Scope:** `locales/**`, `examples/locales/**`, `tools/i18n/**`, `tests/i18n/**`.
- **Содержание:** ключи `ui.*` для HUD и кнопок мини-игры; ключи новых кодов из S-1; каталоги примеров
  `ru` и `zh-Hans` (минимум `ui.*`, `game.*`, `entity.*`); расширение `i18n-no-literals` на текстовые
  поля сцен (`text`, `tooltip_text`, `placeholder_text`, `window_title`, `title`) в `.gd` и `.tscn`
  с фикстурой-провалом и фикстурой-успехом.
- **Сделано, когда:** `i18n-check` код 0, `en` 100 % всех ключей, остальные семь ≥ 95 %; `i18n-no-literals`
  код 0 и находит намеренный литерал в фикстуре; `npm run test:i18n` ≥ 18 без fail; `examples/locales/ru.json`
  и `zh-Hans.json` валидны и проходят `i18n-placeholders`.
- **Запреты:** мягкий режим анализатора; разные наборы ключей по локалям; переводы «пустой строкой».

### S-3 · Runtime: реестр сцен из манифестов, определения и экземпляры
- **Исполнитель:** `Executor Core`. **Зависит от:** S-1. Sequence 10.3.
- **Scope:** `game/runtime/**`, `game/cli/**`, `game/modules/**`, `tests/cli/**`, `tests/modules/**`,
  `tests/runtime/**`.
- **Содержание:** реестр сцен = встроенная карта ядра + `sceneEntries` разрешённых модулей;
  `scene.id.unknown` перечисляет доступные ID сборки; дубль ID диагностируется, а не «кто последний»;
  `entities` из GameSpec создают экземпляры с копией свойств; два экземпляра независимы.
- **Сделано, когда:** N-3 закрыт полностью (включая список `expected` без хардкода); N-6 закрыт;
  `tests/cli` ≥ 11 и `test:modules` ≥ 12 без fail; `run examples/minimal.game.yaml` по-прежнему код 0;
  `scene_registry.gd` остаётся только базовой картой ядра и не содержит модульных сцен.
- **Запреты:** хардкод сцен модулей в ядре; порядок «последний выиграл»; хранить состояние экземпляра
  в определении; менять `examples/**` под удобный результат.

### S-4 · Мини-игра с вводом и состоянием
- **Исполнитель:** `Executor Core`. **Зависит от:** S-3. Sequence 10.4.
- **Scope:** `examples/**`, `game/runtime/**` (сцены и ввод), `tests/cli/**`.
- **Содержание:** `examples/arena.game.yaml` — 2D top-down: игрок, три предмета, счётчик, условие
  победы; управление WASD/стрелки; воспроизводимый headless-ввод `--input <abs.json>`
  (`{"actions":[{"frame":N,"action":"move_right"}]}`) с валидацией пути и опций; отпечаток
  `synapse.world-state.v1` включает позицию игрока и счётчик и не включает локаль и текст.
- **Сделано, когда:** N-5 закрыт: все локали код 0, PNG открыт и описан (игрок сместился, счётчик вырос),
  отпечатки 0/60/120 различаются, между `en`/`de`/`ru`/`zh-Hans` совпадают побайтово; повторный прогон
  идемпотентен; `--input` с несуществующим файлом даёт структурированную ошибку (готовит N-8).
- **Запреты:** «движение ради картинки» без состояния; ввод, зависящий от реального времени; ассеты
  с именами файлов в правилах (INV-3); второй жанр.

### S-5 · Локализованный UI игры
- **Исполнитель:** `Executor Core`. **Зависит от:** S-2, S-4. Sequence 10.5.
- **Scope:** `game/runtime/**`, `examples/**`, `tests/cli/**`.
- **Содержание:** тексты HUD, кнопок и подсказок читаются из каталога по ключу и локали прогона;
  `--lang`/`--locale` доводит локаль до `TranslationServer`; смена локали не меняет отпечаток мира.
- **Сделано, когда:** N-7 закрыт: `i18n-check` и `i18n-no-literals` код 0; PNG на `ru` и `zh-Hans`
  открыты, текст на запрошенном языке, тофу нет, раскладка не ломается (обрезки не видно); отпечатки
  состояния совпадают с `en`; литералов в сценах нет.
- **Запреты:** зашитый текст в `.gd`/`.tscn`; отдельная ветка кода на локаль; подмена шрифта вместо
  перевода; правка `tools/i18n/**` (зона `Locale Auditor` — только предложением в отчёт).

### S-6 · Диагностика и CI
- **Исполнитель:** `Executor Core`. **Зависит от:** S-1, S-2, S-5. Sequence 10.6.
- **Scope:** `game/cli/**`, `game/runtime/**`, `package.json`, `.github/workflows/**`, `AGENTS.md`,
  `README.md`, `tests/cli/**`.
- **Содержание:**
  1. `spec.file.missing` вместо голого `ENOENT`; `runtime.engine.missing` вместо `render_failed/127`;
     `cli.dependency.node_missing` вместо сырого `node: not found`; текст — из каталога, `code` и
     `params` одинаковы на всех локалях; `cli.run.render_failed` сохраняет причину в `params`.
  2. CI: `paths` включает `schema/**`, `examples/**`, `tests/**`, `docs/contracts/**`; шаги —
     `check:contracts`, `test:contracts`, `test:validation`, `test:modules`, `test:i18n`, `test:cli`,
     `test:runtime`, `test:deps`, `i18n-check`, `i18n-no-literals`; npm-скрипты `test:cli` и
     `test:runtime` существуют и запускают соответствующие наборы.
  3. Документация: в `AGENTS.md` убрать утверждение, что репозиторий private; в `README.md` раздел CLI
     (`validate`/`resolve`/`run`, `--lang`, `--state`, `--input`) и требование Node ≥ 20.19 со ссылкой
     на офлайн-установку из `vendor/`.
- **Сделано, когда:** N-8 и N-9 закрыты; PR карточки показывает зелёный непустой набор проверок;
  отдельный PR, меняющий только `examples/**` или `schema/**`, тоже запускает проверки (ссылка на run);
  `git diff --check` пуст; D-022-скан пуст.
- **Запреты:** проверять «зелёность» словами вместо ссылки на run; отключать/сужать существующие шаги;
  добавлять сеть в CI-шаги; менять `schema/**` (зона S-1).

## 4. Что Coordinator делает на старте

1. Создаёт строку «SYN-2 · путь автора…» в «Миссиях» со ссылкой на это ТЗ (или использует созданную
   Warden) и дочернюю страницу «SYN-2 · очередь карточек» с текстами S-1…S-9.
2. Ставит `S-1` и `S-2` в `Ready` (`Sequence` 10.1 и 10.2) — они независимы и идут параллельно.
3. Не выдаёт `S-3` до `Accepted` по `S-1`, не выдаёт `S-4` до `S-3`, не выдаёт `S-7` до закрытия
   `S-1…S-6`.
4. Любое расхождение ТЗ и реальности — в «Замечания» миссии, не в тихую правку очереди.
