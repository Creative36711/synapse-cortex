## A. Вердикт по фазе 1

**Фаза 1 принята — с ограниченной областью действия инвариантов.**

1. Каркас работает: описание проверяется, модули разрешаются, сцена модуля достижима через `run`,
   каталоги живут в восьми локалях, диагностика машинная (`code` + `params` + текст из каталога).
   Это доказано оракулом SYN-2 и повторено на приёмке.
2. Функциональных дефектов, блокирующих фазу 2, не найдено. Найдено девять дефектов
   **доказательства и инструментов** (F-1…F-9): часть из них делает зелёную приёмку неотличимой от
   регрессии.
3. Поэтому формулировки приёмки SYN-2 сохраняются в силе, но читаются узко и только так:
   **INV-12 подтверждён для арены и для текущего набора входов; INV-13 подтверждён для имеющегося
   кода и для литералов, которые ловит текущий анализатор.** Универсального утверждения «инвариант
   защищён» фаза 1 не даёт.
4. Перевод фазы 1 из «работает» в «защищено» — миссия **SYN-3** (`docs/missions/SYN-3.md`,
   очередь `docs/handoff/syn-3-card-queue.md`). Пока SYN-3 не принята, фаза 2 не начинается:
   иначе следующая миссия строится на измерении, которому нельзя верить.

Аккаунты, каталог, публикация, покупки, хостинг, песочница пользовательского кода, GUI-редактор,
второй жанр, сохранения/загрузки, экспорт сборки, мультиплеер, мобильные и Windows-сборки.
Расширение объёма появляется только решением Мастера и новой миссией (R-22). Правка
`tools/godot/**` и `tools/godot/patches/**` по-прежнему запрещена.

## F. Риски и контроль

- **R-23.** Отпечаток v2 ломает совместимость артефактов приёмки SYN-1/SYN-2. Контроль: v1
  читается, сравнение всегда внутри одной версии, в отчёте указывается версия.
- **R-24.** Анализатор литералов на основе настоящего парсера (`gdtoolkit`/`gdparse`) тянет
  Python-зависимость в сборку Node. Контроль: изолированный venv вне `package.json`, fail-closed
  при отсутствии парсера, отдельный шаг CI (`i18n-no-literals --require-parser`), простой путь
  «без парсера» не даёт зелени.
- **R-25.** Реальный ввод ломает детерминизм. Контроль: V-3 требует одинаковый отпечаток при подаче
  одного и того же сценария `InputEvent` дважды подряд.
- **R-26.** Среда 2 ядра / 3 ГБ: параллельные прогоны Godot дают таймауты. Контроль: одна карточка
  в работе, `--frames 120` × 4 локали — не более четырёх процессов подряд, артефакты в Drive.
- **R-27.** Ложная зелень CI возвращается иначе (например, фильтр по `paths`). Контроль: V-9 —
  прогон, в котором шаблон тестов не совпал ни с одним тестом, обязан падать.

## G. Порядок, стоимость, среда

1. B1 → B2 → B3 → B4 → B6 → B8 последовательно (`Executor Core` — один человек, один PR за раз).
   B5 идёт параллельно B1: другой владелец, другая зона.
2. B7 после B1–B6: аудит на чистом клоне, без правок.
3. C1–C3 — после приёмки B-блока, отдельной волной.
4. Среда приёмки: 2 ядра, 3 ГБ, GPU нет. Один прогон 120 кадров — единицы секунд, но сборка
   Godot из исходников на 2 ядрах — больше часа, поэтому движок только из `tools/godot/install.sh`.
5. Сеть — по белому списку (`github.com`, `registry.npmjs.org`, `pypi.org`). `pypi.org` в списке,
   значит `gdtoolkit` ставится; если реестр недоступен — B5 обязана падать, а не пропускать (R-24).
6. Общий бюджет волны: 8 карточек, каждая — один PR в `synapse`, один отчёт. Возврат карточки —
   круг +1, после третьего возврата очередь останавливает Координатор (правило SYN-2 §1.7).

## H. Вопросы Мастеру

**H-1 (одно решение).** Отпечаток мира меняется на v2 (F-1). Это единственный пункт, который
ломает совместимость с артефактами уже принятых миссий. Варианты:

- **v2 сразу** (предлагается): v2 становится единственным для доказательств, v1 читается;
  артефакты SYN-1/SYN-2 остаются в Drive как история, но не сравниваются с новыми.
- **v1 + отдельный `--snapshot`**: отпечаток не трогаем, полный снимок — второй файл.

**H-2…H-4 — приняты по умолчанию, ответа не требуют:**

- *Допущение 1:* `gdtoolkit` разрешён как dev-зависимость в изолированном venv (не в
  `package.json`, не в рантайме ядра).
- *Допущение 2:* порог перевода игровых ключей к концу SYN-3 — 100 % для восьми локалей (C1);
  до приёмки C1 действует текущий порог SYN-2 (≥ 95 %).
- *Допущение 3:* SYN-P1 остаётся закрытой гейтом до приёмки SYN-3; пилоты запускаются после неё.
