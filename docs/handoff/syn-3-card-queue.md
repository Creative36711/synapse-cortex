# SYN-3 · очередь карточек для Coordinator

Передача от Warden, 2026-11-02. Очередь режет миссию SYN-3 (`docs/missions/SYN-3.md`, ТЗ 1.0)
на карточки, готовые к постановке по одной. ТЗ — источник требований, этот документ — источник
**порядка**. При расхождении выигрывает ТЗ, расхождение идёт в «Замечания» миссии.

Notion-копия для исполнителей: дочерняя страница миссии SYN-3 (создаётся Coordinator вместе
с первой карточкой; тексты копируются целиком, ссылок на cortex в карточках быть не может, D-022).

**Состав ролей:** новых ролей не требуется. Зоны: `Contract Architect`, `Executor Core`,
`Locale Auditor` — `synapse`; `Spec Auditor`, `Coordinator`, `Warden` — `synapse-cortex`
(`Executor Platform` в SYN-3 не участвует).

## 1. Правила постановки

1. Одна карточка — одна зона записи. Пересечение зон запрещено; нужно две — две карточки и зависимость.
2. В карточке обязательно: цель, `Scope` (пути в `synapse`), «Сделано, когда» (пункты V-1…V-11
   и INV-1…INV-18), запреты, форма отчёта.
3. Карточка закрывается доказательством: команда, код возврата, артефакт, SHA. «not run», тайм-аут,
   «локально работает» и зелёный CI без проверки на нужном пути — не pass.
4. Контракты (`schema/**`, `docs/contracts/**`) меняются только B1. Молчаливое изменение контракта
   в другой карточке — возврат.
5. `examples/**` после появления не подгоняются под код; правка примера требует абзаца «почему».
6. Ветки и PR — в `main` репозитория `synapse`. Один PR на карточку.
7. Круг инкрементируется при возврате. После третьего возврата одной карточки Coordinator
   останавливает очередь и передаёт решение Warden.
8. Ни одна карточка не ослабляет проверки SYN-2: `test:contracts` 99, `test:validation` 16,
   `test:modules` 18, `test:i18n` 24, `test:deps` 8, `test:runtime` 1, `tests/cli` 20,
   `i18n-check` 8×29 — остаются зелёными; уменьшение чисел — повод для возврата.
9. **Одна карточка в работе.** `Executor Core` ведёт B2 → B3 → B4 → B6 → B8 строго по одной;
   параллельно допустим только B5 (`Locale Auditor`, другая зона).

## 2. Первая выдача: B1 + B5 параллельно

### B1 · Контракт отпечатка мира v2 и таблица ошибок сцены — `Contract Architect`

**Зачем.** Отпечаток v1 не содержит ни локали, ни текста, ни кадра, поэтому его равенство ничего
не доказывает (F-1). Публичный контракт ошибок сцены не описывает два кода, которые автор видит на
пути «сцена из модуля» (F-7).

**Scope.** `docs/contracts/**`, `schema/**`, `docs/decisions/SYN-3.md`.

**Сделано, когда.**

- в `docs/contracts/` есть спецификация отпечатка `synapse.world-state.v2`: перечень полей
  (обязательно `locale`, `frame`, `text`, `tooltip_text`, `visible`, геометрия), смысл
  `fingerprintScope`, порядок нормализации, правило сравнения «только внутри одной версии»;
- схема v2 лежит в `schema/**`, v1 остаётся читаемой схемой без изменений;
- в `docs/contracts/scene-binding.md` §«Что означает каждая ошибка» добавлены `ref.unresolved`
  и `actions.file.missing` с колонками «когда» и «что поправить»;
- в `docs/decisions/SYN-3.md` записано решение по формату со ссылкой на D-058;
- `npm run check:contracts` — код 0, число тестов не уменьшилось; на новую схему добавлены кейсы.

**Запреты.** Не менять формат v1. Не трогать `game/**`. Не вводить коды ошибок вне реестра.

**Отчёт.** V-1 и V-7; SHA BASE/HEAD; список файлов; для каждого нового кейса — что он ловит.

### B5 · Анализатор литералов fail-closed — `Locale Auditor`

**Зачем.** `i18n-no-literals` пропускает многострочный литерал и конкатенацию с нелитеральным
первым операндом (F-5): `scanned=1 user-facing-literals=0`, код 0. INV-13 обходится тремя строками.

**Scope.** `tools/i18n/**`, `tests/i18n/**`, `docs/I18N.md`.

**Сделано, когда.**

- проба `tests/fixtures/i18n/multiline.gd` (`"""…"""` в `text`), `concat.gd`
  (`String.chr(72) + "…"`), `chr.gd`, `plain.gd` — каждая даёт код ≠ 0 с `файл:строка`;
- разбор идёт настоящим парсером GDScript (`gdtoolkit`/`gdparse`) в изолированном venv
  вне `package.json`; самописный токенизатор остаётся только как быстрый предфильтр и не может
  выдать «0 находок» при недоступном парсере;
- при отсутствии парсера проверка завершается кодом ≠ 0 с машинной записью (INV-16);
- `docs/I18N.md` описывает, что именно проверяется и почему «0 литералов» без парсера невозможно;
- `npm run i18n-no-literals` на чистом дереве — код 0 и те же 0 литералов, что приёмка SYN-2
  видела на `6cff12a` (проверка не должна начать «находить» легальные строки без разбора).

**Запреты.** Не менять `locales/**` в этой карточке (это C1). Не ослаблять `i18n-check`.
Не выносить Python-зависимость в `package.json` или в рантайм ядра.

**Отчёт.** V-5, V-9 в части отсутствующего парсера; версия `gdtoolkit`; SHA BASE/HEAD.

## 3. Вторая выдача: B2 (после B1)

### B2 · Отпечаток v2 в runtime — `Executor Core`

**Scope.** `game/**`, `tests/cli/**`.

**Сделано, когда.**

- вложенный запуск получает локаль (`--lang` доходит до capture-процесса) и пишет её в снимок;
- `_snapshot_node` собирает `text`, `tooltip_text`, `title` там, где они есть, и `frame` — в корне;
- прогоны `en` и `de` на 120 кадрах дают **разные** отпечатки; два прогона `en` подряд — побайтово
  равные; `--frames 0/60/120` различаются;
- в выводе есть `fingerprintScope`; v1 читается при `--state-format v1` и не используется
  в доказательствах;
- `tests/cli` дополнены кейсом «локаль меняет отпечаток, но не правила».

**Запреты.** Не менять `schema/**` и `docs/contracts/**` (зона B1). Не ломать `examples/**`.

**Отчёт.** V-2, V-11; имена файлов отпечатков в `Arena/synapse/artifacts`.

## 4. Третья выдача: B3, B4 (последовательно)

### B3 · Ввод арены: событие, а не массив — `Executor Core`

**Scope.** `game/runtime/scenes/**`, `game/input/**`, `tests/runtime/**`.

**Сделано, когда.**

- арена обрабатывает `_unhandled_input`, кнопки `StartButton`/`PauseButton`/`RestartButton`
  подключены через `pressed.connect`;
- сценарий `InputEvent` из `tests/fixtures/input/ui-script.json` воспроизводится дважды с одинаковым
  отпечатком; пауза останавливает кадры, перезапуск сбрасывает счётчик — всё видно в отпечатке;
- `--input` (скриптованные действия) остаётся рабочим и даёт тот же результат, что эквивалентный
  набор событий: автор может играть, приёмка — воспроизводить.

**Запреты.** Не менять поведение `--frames`/`--shot`. Не вводить недетерминизм (время, случайность
без сида).

**Отчёт.** V-3; PNG до/после паузы открыты и описаны.

### B4 · Диагностика вложенного запуска — `Executor Core`

**Scope.** `game/cli/**`, `tests/cli/**`.

**Сделано, когда.**

- `--state /proc/nope/state.json` → `cli.run.state.write_failed`, `params.path` = переданный путь;
- `--input` на отсутствующий файл → `actions.file.missing`;
- `run` без движка → `runtime.engine.missing` (и только этот случай);
- argv вложенного процесса собирается так, что значения с пробелами и дефисами не склеиваются;
- в stderr нет сырых `ENOENT`/`127` без машинной записи.

**Запреты.** Не добавлять коды вне реестра; новый код — только через B1.

**Отчёт.** V-4 с четырьмя записями целиком.

## 5. Четвёртая выдача: B6, затем B7, B8

### B6 · CI-гейт на возврат дефектов измерения — `Executor Core`

**Scope.** `.github/workflows/**`, `tests/**`, `tools/ci/**`.

**Сделано, когда.**

- в CI входят проверки V-2 (локаль меняет отпечаток) и V-5 (многострочный литерал ловится);
- шаг тестов падает, если шаблон не совпал ни с одним тестом (V-9);
- в CI входят `test:runtime` и `i18n-no-literals --require-parser`;
- PR, меняющий только `docs/contracts/**`, гоняет полный набор.

**Запреты.** Не отключать существующие шаги. Не добавлять фильтр `paths`, сужающий прогон.

**Отчёт.** Ссылка на прогон, список шагов, число тестов по каждому пакету.

### B7 · Независимый аудит — `Spec Auditor`

**Scope.** чтение; отчёт.

**Сделано, когда.** Пройдены V-1…V-6, V-8, V-10 на чистом клоне, каждый пункт с командой, кодом
возврата и артефактом; расхождения перечислены списком без правок.

### B8 · Документация равна измеренному — `Executor Core`

**Scope.** `README.md`, `AGENTS.md`, `docs/**` (в `synapse`).

**Сделано, когда.** README говорит, что входит в отпечаток и что равенство отпечатков не значит
равенство картинки; ввод описан как он работает (события + `--input`); перечислены коды `run`;
ссылок на `synapse-cortex` нет.

## 7. Порядок и зависимости

```
B5 ─┐
B1 ─┴─> B2 ─> B3 ─> B4 ─> B6 ─> B7 ─> B8 ─> приёмка SYN-3 ─> C1, C2, C3 ─> SYN-P1
```

B1 и B5 — параллельно (разные владельцы, разные зоны). B2 без B1 невозможен: формат отпечатка
задаёт контракт. B6 без B2 и B5 бессмыслен: нечего ставить в CI. B7 — только после B6 и на чистом
клоне, иначе это самопроверка исполнителя, а не аудит.

## 8. Что Coordinator не делает

Не ставит карточки «пачкой» — очередь читается по одной; не меняет тексты карточек; не закрывает
замечания Warden своими правками; не выдаёт B2 до закрытия B1. Вопросы по существу — Warden,
вопросы про доступ к репозиторию — Мастер (D-022).
