# SYN-1 · очередь карточек для Coordinator

Передача от Warden. Очередь режет миссию SYN-1 (`docs/missions/SYN-1.md`, ТЗ 1.1) на карточки,
готовые к постановке по одной. ТЗ — источник требований, этот документ — источник **порядка**.
При расхождении выигрывает ТЗ, а расхождение идёт в «Замечания» миссии.

Notion-копия (для исполнителей): «SYN-1 · очередь карточек» — дочерняя страница миссии
`40c6f0cf-5705-8128-ad44-fba3d8090400`.

**Состав ролей на момент передачи (2026-11-02):** все семь `Активна`, зоны по D-020/D-022 —
`Executor Core` и `Contract Architect` (`synapse`), `Locale Auditor` (`synapse`, локали),
`Executor Platform` (транспорт и платформа), `Coordinator` (очередь), `Spec Auditor` и Warden
(проверки). Карточки K-2, K-6, K-7, K-10 уходят владельцам зон, а не `Executor Core`.

Исполнители миссии видят только `synapse` (D-022), поэтому ссылки на файлы этого репозитория
в карточки не попадают: требования копируются в текст карточки.

## 1. Правила постановки

1. Одна карточка — одна зона записи. Пересечение зон в одной карточке запрещено; если нужно —
   две карточки и зависимость между ними.
2. В карточке обязательно: цель, `Scope` (пути в `synapse`), «Сделано, когда» (пункты оракула
   O-1…O-13 и инварианты INV-1…INV-10), запреты, форма отчёта.
3. Карточка закрывается только доказательством: команда, код возврата, артефакт (скриншот
   открыт и описан), SHA. «not run», тайм-аут и «локально работает» — не pass.
4. Контракты (`docs/contracts/**`, `schema/**`) меняются только карточкой K-2 или карточкой,
   в которой изменение контракта явно названо. Молчаливое изменение контракта — возврат.
5. `examples/**` после появления не подгоняются под код; правка примера требует абзаца
   «почему» в отчёте.
6. Ветки и PR — в `main` репозитория `synapse`. Один PR на карточку или на пару связанных.
7. Круг инкрементируется при возврате карточки. После третьего возврата одной карточки
   Coordinator останавливает очередь и передаёт решение Warden.

## 2. Порядок и зависимости

```
K-1 ─→ K-2 ─┬─→ K-3 ─┬─→ K-5 ─┬─→ K-9
            │        │        │
            │        ├─→ K-8 ─┴─→ K-10
            └─→ K-4 ─┘
K-6 ─→ K-7 ─┘ (i18n-инструменты можно вести параллельно K-3, но каталоги появляются до K-5)

K-11 — вне критического пути (можно ставить в любой момент).
K-13 — вне критического пути (инструкция для агентов в `synapse`, кроме K-11, ничего не ждёт).
K-14 — вне критического пути миссии и вне активного цикла: только в окно паузы, по команде Warden.
```

Параллелить можно: `K-3 ∥ K-4`, `K-6 ∥ K-4`, `K-11 ∥ K-13 ∥ любую`. Нельзя параллелить `K-5` с `K-3`.

## 3. Карточки

### K-1 · Песочница и стартовый снимок
- **Исполнитель:** `Executor Core`. **Зависимостей нет.**
- **Цель:** доказать, что Godot работает в песочнице и зафиксировать базу, от которой считается
  вся миссия.
- **Scope:** `tools/godot/**` — только запуск; правок нет.
- **Сделано, когда:** стартовый SHA `main` записан в отчёт; `tools/godot/install.sh --check`
  код 0; `shot_1.png` и `shot_2.png` получены, **оба открыты и описаны** (O-1); `godot --headless
  --path game --quit` код 0 без ошибок парсинга (O-2).
- **Уточнение по факту (2026-11-03):** на старте миссии каталога `game/` в репозитории нет — его
  создаёт K-3. Значит O-2 на K-1 недостижим: карточка сдаётся как диагностика (O-1 pass, O-2 rc 1
  с зафиксированной причиной, `Check=fail`, правок кода нет), а прогон O-2 переносится в K-3 и
  в финальный оракул K-12. Подменять проверку «похожим» прогоном нельзя.
- **Запреты:** чинить `tools/godot/**`; трогать `game/**` сверх запуска.

### K-2 · Контракты `GameSpec`, манифеста и ошибок
- **Исполнитель:** `Contract Architect` (роль активна с 2026-11-02; зона `docs/contracts/**`,
  `schema/**`). **Приёмка:** Warden; соответствие кода контрактам позже проверяет `Spec Auditor`
  (O-4, O-5, O-8). **Зависит от:** K-1.
- **Цель:** зафиксировать три контракта до кода, чтобы валидатор и рантайм не расходились.
- **Scope:** `schema/**`, `docs/contracts/**`, `docs/decisions/SYN-1.md`.
- **Содержание:** формат описания игры (предложение — YAML, решение фиксируется здесь же
  абзацем «почему»); формат манифеста модуля (версия, зависимости, конфликты, семантическая
  версия); реестр кодов ошибок — код + параметры, текст только из каталога локализации (INV-9).
- **Сделано, когда:** схемы лежат в репозитории, у каждой есть пример-минимум и пример-ошибка;
  реестр кодов покрывает: неизвестное поле, неверный тип, цикл зависимостей модулей, отсутствующий
  ключ локализации.
- **Запреты:** писать реализацию валидатора; вводить строки диагностики в код (только коды).

### K-3 · Валидатор с человекочитаемой диагностикой
- **Исполнитель:** `Executor Core`. **Зависит от:** K-2.
- **Остаток от K-1 (факт 2026-11-03):** в `synapse` нет каталога `game/`, поэтому O-2
  (`godot --headless --path game --quit`) вернул rc 1 «Invalid project path specified». K-1
  закрыта как диагностика с `Check=fail`, код не чинился. Эта карточка создаёт эталонный проект
  (`game/project.godot` и минимальную сцену) и **обязана повторить O-2** — rc 0 и отсутствие
  ошибок разбора GDScript; приёмка не принимает карточку без этого прогона.
- **Scope:** `game/cli/**`, `game/validation/**`, `examples/**` (создание), фикстуры в `tests/`.
- **Сделано, когда:** O-3 (валидный пример — код 0, машиночитаемый `ok`); O-4 (сломанный пример —
  код ≠ 0, в тексте есть поле, ожидание и фактическое значение); O-6-подготовка — фикстуры
  лежат в репозитории; на десяти намеренно сломанных описаниях по тексту понятно, что править
  (INV-6).
- **Запреты:** сообщение об ошибке строкой в коде; «универсальный» текст вроде «неверный формат».

  артефакты и список файлов.
- **Запреты:** «закрыть» пункт без артефакта; сдавать на грязном рабочем дереве.

### K-13 · `AGENTS.md` в `synapse`: два репозитория и готовые инструменты
- **Исполнитель:** `Executor Core`. **Приёмка:** Warden. **Зависит ни от чего** (можно параллельно).
- **Зачем:** `AGENTS.md` — инструкция для любого агента, который впервые открыл репозиторий,
  и сейчас она врёт в одном месте и молчит в другом. Строка «The repository is private: the agent
  needs GitHub access to `Creative36711/synapse`» неверна: репозиторий публичный, лицензия MIT
  (K-11). Модель двух репозиториев не описана вовсе, поэтому агент не понимает, почему в
  `synapse` нет документов платформы, и ищет их.
- **Scope:** `AGENTS.md` (только этот файл).
- **Сделано, когда:** (1) строка про приватность заменена на «публичный, MIT, клонируется без
  токена»; (2) добавлен короткий раздел в начале: `Creative36711/synapse` — открытое ядро и
  инструменты, всё нужное для локальной сборки и экспорта игры лежит здесь; закрытая часть
  (транспорт, платформа) живёт в `Creative36711/synapse-cortex`, роли ядра её не видят и ссылок
  на неё в этом репозитории быть не должно; (3) явно сказано, что сборки Godot/Blender/медиа
  лежат в репозитории намеренно, и пересборка (`build_from_source.sh`) — отдельная задача,
  а не «по ходу»; (4) все команды из разделов 1, 4, 5 по-прежнему совпадают с фактическими
  путями (`git ls-files tools/` подтверждает); (5) в отчёте — `grep -n "private" AGENTS.md`
  с пустым выводом и кодом 1.
- **Запреты:** менять `README.md`, `LICENSE`, `NOTICE` (зона K-11); трогать `tools/**`; писать
  вместо факта обещания («будет добавлено»).

### K-14 · Гейт версии транспорта (окно паузы, не в активном цикле)
- **Исполнитель:** `Executor Platform` (владелец `tools/script-cat/**`); приёмка — Warden.
- **Когда ставить:** только по команде Warden в окно паузы, вместе с остальным батчем транспорта.
  В активном автоцикле карточка не выдаётся (D-027).
- **Зачем:** PR #26 и #27 изменили поведение транспорта без подъёма `@version`; `version-oracle.mjs`
  сверяет только шапку с `SCRIPT_VERSION`, поэтому «контент изменился, номер — нет» проходит незаметно,
  а Мастер не может понять по номеру, какой код стоит в браузере. Аварии не было: Мастер заказал
  #26/#27 сам, экспорт и импорт работают, отдельный релиз ради номера не выпускается (D-027,
  «Уточнение по факту»). Карточка — про дрейф номера, а не про починку текущего состояния.
- **Scope:** `tools/script-cat/src/**`, `tools/script-cat/build.mjs`, `tools/script-cat/version-oracle.mjs`,
  `tools/script-cat/tests/**`, `tools/script-cat/relay.user.js` (сборка), `docs/scriptcat-update.md`.
- **Сделано, когда:**
  1. сборка пишет в бандл отпечаток исходников (список «путь + sha256» в метаданных, а не в промпте);
  2. версии развязаны: `regulation-oracle.mjs` больше не требует равенства
     «версия digest == версия REGULATION.md»; digest объявляет, какую версию полного регламента он
     отражает, и имеет собственный счётчик, поэтому правка `REGULATION.md` без изменения промптов
     не требует переустановки userscript (сейчас требует — D-027);
  3. `version-oracle.mjs` умеет сравнить отпечаток и `@version` с предыдущим состоянием `main`
     и падает, если контент изменился, а версия — нет (проверка не должна мешать легитимному
     bump-версии в одном PR);
  4. у пробы есть фикстура-провал (контент изменён, версия та же) и фикстура-успех (версия поднята);
  5. `npm run verify` зелёный; в отчёте — вывод новой пробы и `@version` до/после.
- **Запреты:** «мягкий» режим, который печатает предупреждение и возвращает 0; правка промптов
  в этой карточке (промпты — только отдельным батчем с явной пометкой о переустановке).

## 4. Что Coordinator сообщает Warden

После каждой карточки — три строки: `карточка`, `SHA`, `оракул: закрыто/нет + что осталось`.
Раз в круг — отчёт о рисках: R-01, R-02, R-12, R-16, R-17, R-18 из ТЗ.
`accept` миссии выносит только Warden (§9 ТЗ).
