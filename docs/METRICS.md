# Метрики фаз и способ их фактического замера

Считать успехом повторное использование, а не число аккаунтов. Для каждой метрики указан
источник данных: метрика без источника — пожелание, а не метрика.

## Фаза 0 (сейчас)

| Метрика | Источник | Целевое значение |
|---|---|---|
| Готовность контура: транспорт + Notion + Gateway | этот документ и `PHASE0.md` | все проверки зелёные, живой пилот пройден |
| Число интервью с авторами/игроками | заметки интервью | 5–10 |
| Открытые вопросы, блокирующие запуск | база «Обратная связь» | 0 блокирующих |

## Фаза 1 (локальный каркас)

| Метрика | Источник | Целевое |
|---|---|---|
| Можно ли описать игру декларативно и проверить её | CLI: код 0 и отчёт валидатора | да, на примере размером ≤ 1 экрана YAML |
| Понятность ошибок валидатора | ручная проверка: по тексту ошибки можно исправить без вопросов | ≥ 8 из 10 намеренно сломанных GameSpec |
| Число действий разработчика вручную | журнал миссии | ≤ 1 (только запуск CLI) |
| Время до первого рабочего результата | замер от `git clone` до запуска | ≤ 10 минут в песочнице |

| Метрика | Источник |
|---|---|
| Оборот продаж, а не только удержание платформы | журнал операций |

## Правила замера

- Метрика, которую нельзя получить из существующих данных, требует сначала инструмента замера,
  а не оценки «на глаз».
- Незапущенная проверка не считается пройденной; «работает у меня» — не данные.
- Ретроактивные метрики не досочиняются: если замер не вёлся, так и пишется.
