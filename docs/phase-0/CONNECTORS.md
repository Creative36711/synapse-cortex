## Supabase — главная находка

**Текущее состояние:** организация `Creative36711` существует, **проектов нет**.

Бесплатный уровень закрывает сразу четыре статьи из `COST_MODEL.md` §9: сервер, резервное
копирование, хранилище файлов и аутентификацию.

### Лимиты (по данным сторонних обзоров за 2026 год, не по официальной странице — сверить перед оплатой)

| Ресурс | Free | Pro, от $25 / мес |
|---|---|---|
| Размер БД | 500 МБ | 8 ГБ, далее $0,125 / ГБ |
| Хранилище файлов | 1 ГБ | 100 ГБ, далее $0,021 / ГБ |
| Egress | 5 ГБ | 250 ГБ, далее $0,09 / ГБ |
| Активные пользователи | 50 000 MAU | 100 000 MAU |
| Максимальный размер файла | 50 МБ | 500 ГБ |
| Автоматические бэкапы | **нет** | ежедневно, хранение 7 дней |
| Пауза при простое | **через 7 дней** | никогда |
| Активных проектов | 2 | без ограничений |

Pro включает $10 вычислительных кредитов, что покрывает один Micro-инстанс: организация Pro
с одним проектом обходится в $25 в месяц целиком. **Это ровно тот потолок, который Мастер
подтвердил.**

### Риски бесплатного уровня, которые нужно удерживать

1. **Нет автоматических бэкапов.** Потеря базы на Free — потеря данных. Компенсация: регулярный
   дамп в закрытый репозиторий или на Диск. Это нужно заложить в регламент как обязательную
   процедуру, а не надеяться на авось.
2. **Пауза через 7 дней без обращений.** Для Фазы 0–3 не страшно, для Фазы 4 со живыми авторами —
   уже нет. Переход на Pro привязан к Фазе 4.
3. **500 МБ БД и 1 ГБ файлов.** Для хранения артефактов игр этого мало. Хранилище ассетов всё равно
   остаётся отдельным решением — см. Решение 8 (объектное хранилище как основа), Supabase Storage
   не подменяет его на объёмах Фазы 4+.

### Что нужно от Мастера

Создать проект **не могу я**: создание проекта требует пароль базы данных, а пароль — это секрет.
По регламенту секреты владелец вводит сам, я не выдумываю их и не передаю в чате.

- Создай проект в организации `Creative36711` через панель Supabase;
- либо дай отдельное разрешение — и пароль вводишь сам.

После создания я смогу работать с БД, хранилищем и edge-функциями через коннектор.

## Linear — не сейчас

**Текущее состояние:** команда `Creative Arena` (`CRE`) создана 2026-10-22, проектов нет,
внутри 4 онбординг-задачи (`CRE-1` … `CRE-4`). По сути — пустой рабочее пространство.

**Рекомендация: не вводить на Фазе 0.**

Причина не в Linear, а в дисциплине. Notion уже ведёт миссии, роли и приёмку — это слой
управления. Linear — слой инженерных задач. Пока нет ни одной задачи Фазы 1, второй трекер
означает второй источник истины и лишнюю синхронизацию руками. Вводить его сейчас —
создавать работу по поддержанию двух реестров вместо работы над продуктом.

**Когда вводить:** на Фазе 1, вместе с первыми инженерными задачами. Правило раздела фиксируется
сразу и не меняется потом:

| Слой | Где | Что там живёт |
|---|---|---|
| Управление | Notion | Миссия, ТЗ, оракул приёмки, роли, решения |
| Инженерия | Linear | Задачи, подзадачи, связи с PR открытого репозитория |

Одно направление связи: карточка миссии в Notion ссылается на проект в Linear. Обратного
не требуется.

## Google Docs / Sheets / Slides

Дублируют репозиторий, поэтому использовать выборочно — только там, где нужно совместное
редактирование человеком:

- **Sheets** — таблица метрик, если Мастер хочет следить за ними глазами, а не через коммиты;
- **Docs** — конспекты интервью, если Мастер их пишет или правит сам;
- **Slides** — только если понадобится презентация для внешних.

Для всего остального источник истины — репозиторий, а не документ.

## Чего в коннекторах нет

Ни один из подключённых сервисов не даёт:

- исполнения игр и проверки рендером — это Godot в открытом репозитории;
- управления репозиториями — это GitHub;
- доставки ходов между агентами — это ScriptCat и Drive Gateway.

Коннекторы закрывают учет и хранение, но не заменяют продуктовый конвейер.
