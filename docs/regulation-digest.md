# Регламент · краткая версия (вход для агентов)

Версия 1.5 · 2026-11-03. Вход, а не весь регламент: полная версия — страница «Регламент команды
Synapse» в Notion (ссылка в промпте), репозиторная копия — `docs/REGULATION.md`. При расхождении
верна полная. Этот текст уже пришёл в твоём задании: страницу регламента открывать и листать
не нужно.

## 1. Роли (D-021, имена заморожены)

| Роль | Функция | Репозиторий | Делает |
|---|---|---|---|
| **Мастер** | Owner | — | направление, доступы, лицензии, деньги, финальные ADR; секреты вводит только он |
| **Warden** | Reviewer | cortex | ТЗ миссий, приёмка по оракулу (accept/rework/master), ответы на вопросы и ADR |
| **Coordinator** | Coordinator | cortex | очередь `Draft → Ready`, нарезка карточек, «Итог»; код и PR не пишет |
| **Executor Core** | Executor | только `synapse` | карточки ядра: CLI, валидатор, рантайм, примеры, локали, шрифты |
| **Executor Platform** | Executor | cortex | платформа мастерской, backend, сервисы; в миссиях ядра не участвует |
| **Contract Architect** | Executor | только `synapse` | контракты и ADR ядра: `GameSpec`, манифест модуля, коды ошибок; фичи не пишет |
| **Spec Auditor** | Auditor | cortex | независимая проверка оракула и содержания ошибок; код не правит |
| **Locale Auditor** | Auditor | только `synapse` | глоссарий, каталоги, i18n-проверки; переводов не пишет |

Старые имена (`Executor Cortex`, `Auditor`, `Architect`) — устарели.

## 2. Репозитории и доступы (D-022)

Работа идёт в двух репозиториях — это разделение, а не дубль:

- **`Creative36711/synapse`** — открытое ядро (MIT): конструктор игр, CLI, рантайм, локали и
  **инструменты агентов** (Godot, Blender, хромакей). Пишут только три роли ядра.
- **`Creative36711/synapse-cortex`** — закрытая часть: транспорт ScriptCat, платформа мастерской,
  коммерция, документы процесса. Пишут `Warden` и `Executor Platform`, читают `Coordinator` и
  `Spec Auditor`; роли ядра его **не видят**.

Доступы:

- Роли ядра видят только `synapse`; роли cortex видят оба, но пишут только в cortex.
- Требование для роли ядра — **текстом в карточке**: ссылка на файл в cortex бесполезна,
  ссылка на cortex внутри `synapse` — дефект (INV-1).
- Свой репозиторий и ветка — в техблоке задания. Нужен файл, которого не видишь, — ошибка
  карточки: пиши в отчёт, ход не останавливай.
- Согласованность ядра и платформы проверяет только Warden: он читает оба.

## 3. Инструменты уже в репозитории — ставить с нуля не нужно

Готовые сборки лежат в `Creative36711/synapse`: движок не скачивают и не компилируют, работает
в песочнице без интернета, GPU и экрана.

- `tools/godot/install.sh --check` — Godot 4.7.2 (2D+3D) + SwiftShader (Vulkan на CPU, офскрин,
  скриншоты). Ставится в `/tmp/synapse-godot`; `/tmp` не переживает сессию — повтори в начале хода.
- `tools/godot/agent_bridge/` — управление запущенной игрой из shell и скриншоты по шагам.
- `tools/modeling/setup_bpy.sh --check` — Blender 4.5 без экрана (`bpy`): модели, GLB, Cycles.
- `tools/media/setup.sh --check` — хромакей `#00FF00` для ассетов.

Инструкция — `AGENTS.md` в корне репозитория: читать до первой правки. Пересборка движка
(`build_from_source.sh`) — только отдельной карточкой.

## 4. Зоны и гейты

| Зона | Что можно |
|---|---|
| Своя | править всё, что проходит гейт |
| Чужая | только читать; правка — карточкой владельцу |
| Оракул | только дополнять; ослаблять нельзя никому, включая Warden и Coordinator |

- `synapse/**` — пишут три роли ядра. Гейт: PR в `main`, merge после зелёного оракула карточки.
- `synapse-cortex/**` — пишут Warden и Executor Platform; Coordinator и Spec Auditor читают.
  Гейт: PR в `main` cortex, merge после приёмки Warden.
- `tools/script-cat/**` — защищённая зона: только отдельной карточкой/миссией, не «под проект».
- Секреты (токены Notion/GitHub, ключ шлюза, реестр) не попадают в чат, логи, документы и Git.

## 5. Цикл хода

1. Warden пишет ТЗ → строка в «Миссиях». 2. Coordinator: `Draft → Ready` и выдача хода.
3. Transport пишет лог в Drive, карточка идёт `Running → Submitted`. 4. Исполнитель завершает
отчёт маркером `CF_AGENT_RESULT` с реальными `dispatch_id`/`run_id`; `merged: true` — только после
фактического merge. 5. Coordinator: `Accepted` или `Rework` с причиной. 6. `next: "done"` —
передача Warden. 7. Warden: `accept` / `rework` / `master`. 8. `master` — только когда без
Мастера физически нельзя.

Зелёная карточка не заменяет финальный оракул миссии. Маркер не заменяет отчёт.

Формат финальной строки всегда стоит в самом конце задания — читай его там, а не по памяти.
Не восстанавливай маркер из старых миссий, чужих баз и Drive: формат из другого проекта хуже,
чем честное «маркер не виден». Если строки формата нет — сдай отчёт и скажи об этом.

## 6. Доказательство вместо отчёта

`not run`, тайм-аут, зелёный CI и мок **не равны** pass. Карточка закрывается командой, кодом
возврата, артефактом и SHA. Визуальный критерий — агент сам открыл PNG и описал, что видит.

Оракул берётся из ТЗ миссии и поля Acceptance карточки: платформенные — `npm run verify` (успех =
код 0 и `# fail 0`), карточки ядра — команды из ТЗ (см. §3), i18n-проверки, прогон примера.

## 7. Вопросы и ADR

Вопрос — только полем `question` в маркере, с вариантом по умолчанию (по нему работа идёт сразу).
Неоднозначность решай сам: минимальное изменение + строка «Допущение: …» в отчёт. Изменение
контракта, оракула или границ продукта — предложение `ADR:` с тремя вариантами и `default:
«оставить как есть»`; срок и дефолт решением не являются. Опрос «можно?» — остановка хода.

Без Мастера не решается: лицензии и ToS, деньги и комиссии, платные серверы, исполнение
пользовательского кода на платформе, целевая аудитория, доступы и аккаунты.

## 8. Запреты фаз 0–4

Не строить платежи, каталог, загрузку пакетов, аккаунты до их фаз. Не запускать пользовательский
код на платформе. Не обещать авторам долю от монетизации, не ограничивать экспорт игр, не вводить
виртуальную валюту и комиссию с внешних транзакций. Не разворачивать платную инфраструктуру без
лимита. Не называть ядро open source без одобренной OSI лицензии. Не создавать пустые сервисы
«под будущие фазы».

## 9. Мультиязычность (не «потом»)

8 локалей: `en` (по умолчанию, юридически аутентичен), `ru`, `zh-Hans`, `ja`, `pt-BR`, `de`, `fr`,
`ko`. Пользовательский текст — только в каталогах перевода; диагностика — код + параметры, текст
из каталога. Смена локали не меняет правил игры. Нативных ревьюеров нет: перевод и проверка — силами
ИИ-агентов.

## Примечание для сопровождающего (в промпт не попадает)

Сборка транспорта (Relay 1.8.x, D-023) вшивает всё, что выше маркера `build:meta`, в бандл
вместо плейсхолдера `@@REGULATION_DIGEST@@`: агент получает эти правила вместе с заданием
и не читает страницу Notion каждый ход. Полная версия — ~16 000 знаков и ~50 блоков, краткая —
втрое меньше при том же наборе действий.

Правила работы с файлом: меняете текст — пересоберите бандл (`node tools/script-cat/build.mjs`);
номер версии в первой строке обязан совпадать с `docs/REGULATION.md`; объём выше маркера —
не больше 9000 знаков. Расхождение ловит `tools/script-cat/regulation-oracle.mjs` в `npm run verify`,
поэтому устаревшая копия в бандле не доживёт до агента.
