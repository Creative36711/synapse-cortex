# Регламент · краткая версия (вход для агентов)

Версия 1.2 · 2026-11-03. Это **вход**, а не весь регламент: полная версия — `docs/REGULATION.md`
в `synapse-cortex` и страница «Регламент команды Synapse» в Notion. Если краткая версия расходится
с полной, верна полная, а расхождение — дефект: его чинит Warden в тот же день.

Зачем файл: полный регламент — ~16 000 знаков и ~50 блоков. Читать его каждый ход дорого и
медленно; агенту в ходе нужны роли, зоны, запреты и порядок, а не история решений.

## 1. Роли (D-021, имена заморожены)

| Роль | Функция | Репозиторий | Делает |
|---|---|---|---|
| **Мастер** | Owner | — | направление, доступы, лицензии, деньги, финальные ADR; секреты вводит только он |
| **Warden** | Reviewer | cortex (видит оба) | ТЗ миссий, приёмка по оракулу (accept/rework/master), ответы на вопросы и ADR |
| **Coordinator** | Coordinator | cortex (видит оба) | очередь `Draft → Ready`, нарезка карточек, «Итог»; код и PR не пишет |
| **Executor Core** | Executor | только `synapse` | карточки ядра: CLI, валидатор, рантайм, примеры, локали, шрифты |
| **Executor Platform** | Executor | cortex | платформа мастерской, backend, сервисы; в миссиях ядра не участвует |
| **Contract Architect** | Executor | только `synapse` | контракты и ADR ядра: `GameSpec`, манифест модуля, коды ошибок; фичи не пишет |
| **Spec Auditor** | Auditor | cortex (видит оба) | независимая проверка оракула и содержания ошибок; код не правит |
| **Locale Auditor** | Auditor | только `synapse` | глоссарий, каталоги, i18n-проверки; переводов не пишет |

Старые имена (`Executor Cortex`, `Executor` без уточнения, `Auditor`, `Architect`) — устарели.

## 2. Доступы (D-022)

- Роли ядра (`Executor Core`, `Contract Architect`, `Locale Auditor`) видят **только** `synapse`.
- Роли cortex (`Warden`, `Coordinator`, `Executor Platform`, `Spec Auditor`) видят **оба**, но
  пишут только в `synapse-cortex`.
- Следствие для карточек: требование формулируется **текстом в карточке**; ссылка на файл в
  `synapse-cortex` бесполезна исполнителю, ссылка на cortex внутри `synapse` — дефект (INV-1).
- Согласованность ядра и платформы проверяет только Warden: он читает оба репозитория.

## 3. Зоны и гейты

| Зона | Что можно |
|---|---|
| Своя | править всё, что проходит гейт |
| Чужая | только читать; правка — карточкой владельцу |
| Оракул | только дополнять; ослаблять нельзя никому, включая Warden и Coordinator |

- `synapse/**` — пишут три роли ядра. Гейт: PR в `main`, merge после зелёного оракула карточки.
- `synapse-cortex/**` — пишут Warden и Executor Platform; Coordinator и Spec Auditor читают.
  Гейт: PR в `main` cortex, merge после приёмки Warden.
- `tools/script-cat/**` — защищённая зона: только отдельной карточкой/миссией, не «под проект».
- Секреты (токены Notion/GitHub, ключ шлюза, реестр) не попадают в чат, логи, документы и Git.

## 4. Цикл хода

1. Warden пишет ТЗ → строка в «Миссиях». 2. Coordinator переводит `Draft → Ready`, выдаёт ход.
3. Transport пишет лог в Drive, карточка идёт `Running → Submitted`. 4. Исполнитель завершает
отчёт маркером `CF_AGENT_RESULT` с реальными `dispatch_id`/`run_id`; `merged: true` — только после
фактического merge. 5. Coordinator ставит `Accepted` или `Rework` с причиной. 6. `next: "done"` —
передача Warden. 7. Warden выносит `accept` / `rework` / `master`. 8. `master` — только когда без
Мастера физически нельзя.

Зелёная карточка не заменяет финальный оракул миссии. Маркер не заменяет отчёт.

## 5. Доказательство вместо отчёта

`not run`, тайм-аут, зелёный CI и мок **не равны** pass. Карточка закрывается командой, кодом
возврата, артефактом и SHA. Визуальный критерий — агент сам открыл PNG и описал, что видит.

Оракул cortex (`synapse-cortex`, из корня): `npm run scriptcat:check`, `npm run scriptcat:guard`,
`npm test`, `npm run test:regression`, `npm run verify` (успех = код 0 и `# fail 0`).

## 6. Вопросы и ADR

Вопрос — только полем `question` в маркере, с вариантом по умолчанию (по нему работа идёт сразу,
не дожидаясь ответа). Неоднозначность решается самостоятельно: минимальное изменение + строка
«Допущение: …» в отчёт. Изменение контракта, оракула или границ продукта — предложение `ADR:`
с тремя вариантами и `default: «оставить как есть»`; срок и дефолт решением не являются.

Без Мастера не решается: лицензии и ToS, деньги и комиссии, платные серверы, исполнение
пользовательского кода на платформе, целевая аудитория, доступы и аккаунты.

## 7. Запреты фаз 0–4

Не строить платежи, каталог, загрузку пакетов, аккаунты до их фаз. Не запускать пользовательский
код на платформе. Не обещать авторам долю от монетизации, не ограничивать экспорт игр, не вводить
виртуальную валюту и комиссию с внешних транзакций. Не разворачивать платную инфраструктуру без
лимита. Не называть ядро open source без одобренной OSI лицензии. Не создавать пустые сервисы
«под будущие фазы».

## 8. Мультиязычность (не «потом»)

8 локалей: `en` (по умолчанию, юридически аутентичен), `ru`, `zh-Hans`, `ja`, `pt-BR`, `de`, `fr`,
`ko`. Пользовательский текст — только в каталогах перевода; диагностика — код + параметры, текст
из каталога. Смена локали не меняет правил игры. Нативных ревьюеров нет: перевод и проверка — силами
ИИ-агентов.
